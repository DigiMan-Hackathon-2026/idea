# 첫 지역·퀘스트 후보 선택 가이드

작성일: 2026-11-21 · 상태: 인터뷰 실행 전 선택 절차

이 가이드는 익명 인터뷰 사건을 첫 타깃·문제, 지역, 퀘스트 후보로 좁히는 순서를 정의한다. 점수는 근거를 비교하기 위한 표지판이며 사용자 사례·현장 사실·권리 확인을 대신하지 않는다.

## 산출물

선택이 끝나면 다음 다섯 가지가 서로 연결돼야 한다.

1. `synthesis/YYYY-MM-round-NN.md`: 반복 사건·반대 사례와 문제 판단
2. `region-candidates/<지역>.md`: 지역별 사례·검증 가능성·제외 이유
3. `quest-candidates/<지역-행동>.md`: 3~5단계와 사실·권리 register
4. D04·D05·D06 결정 기록: 선택·대안·무효화 조건
5. 변경된 B2C spec·screen·test commit

인터뷰 문장을 곧바로 제품 요구로 옮기지 않고 문제 → 지역 → 퀘스트 세 gate를 통과한다.

## evidence ID

개인 식별 없이 근거를 연결한다.

인터뷰 사건·관찰을 ID로 승격하는 최소 필드와 독립성 판정은 [evidence coding 가이드](EVIDENCE_CODING_GUIDE.md)를 따른다.

| 형식 | 의미 | 예 |
| --- | --- | --- |
| `E-P01-01` | P01의 첫 최근 사건 | 포기·대체 행동 한 건 |
| `O-P01-01` | P01 안내 예시 관찰 | 도움 전 다음 행동 탐색 |
| `F-R01-01` | 지역 R01 현장·공식 사실 | 혼자 이용 조건 확인 |
| `C-Q01-01` | quest Q01 콘텐츠 근거 | 주소·가격 source row |
| `X-01` | 반대·제외 근거 | 가격이 유일한 포기 이유 |

ID는 원본 파일의 section을 가리킬 뿐 이름·연락처·정확한 개인 주소를 포함하지 않는다. 같은 사건을 여러 pattern과 연결할 수 있지만 독립 사례 수에는 한 번만 센다.

## 독립 사례

다음은 서로 다른 사건으로 셀 수 있다.

- 서로 다른 참여자가 경험한 별도 사건
- 같은 참여자라도 시점·장소·의사결정·대체 행동이 분명히 다른 사건

다음은 독립 사례 수를 늘리지 않는다.

- 한 사건을 “혼자 불안”, “주문 불안”, “일본어 부족” 세 문장으로 나눈 것
- 진행자의 가정이나 가상 예시 동의
- 다른 사람 이야기를 들었다는 전언
- 같은 참여자의 같은 사건을 후속 질문에서 반복한 답
- stimulus를 보고 “좋다”고 말한 반응만 있는 경우

합성 표에는 참여자 수와 사건 수를 함께 적고, 서로 독립적이지 않을 수 있는 군집을 표시한다.

## 1단계: 문제 gate D04

### 통과 후보

현재 “안내 부족 때문에 새 장소를 포기·지연·대체한다” 가설은 다음을 모두 확인할 때 유지 후보가 된다.

- 최근 실제 사건이 독립 참여자 두 명 이상에게 있음
- 각 사건에 원래 행동, 포기·변경 순간, 실제 대체 행동이 있음
- 부족한 정보가 무엇인지 구체적이며 단순 아이디어 호감이 아님
- 가격·시간·동행·예약 불가만이 유일 원인이 아님
- 안내 예시에서 도움 없이 가치와 다음 행동을 이해한 관찰이 있음
- 반대 사례와 안내로 해결할 수 없는 범위를 함께 기록함

표본이 작으므로 이 조건은 시장 수요 “검증 완료”가 아니라 첫 구현 가설 유지 기준이다.

### 수정 후보

사건은 반복되지만 아래 중 하나면 타깃·문제 문장을 수정한다.

- 재방문 관광객보다 거주자·유학생에서만 반복
- 새 장소 발견보다 주문·입장·예약 절차에서만 반복
- 일본어 번역보다 혼자 이용 가능 여부가 핵심
- 완료 기록보다 시작 전 조건 확인이 선택을 바꿈

### 보류·폐기 후보

- 안내가 있어도 가격·시간·동행·예약 제한 때문에 행동하지 않음
- 실제 포기 사건 없이 미래 사용 의향만 있음
- 진행자 설명 후에만 가치를 이해함
- 안전·의료·법률처럼 P0 안내로 책임 있게 다루기 어려움

## 2단계: 지역 gate D05

문제 gate를 통과한 사건에 등장하거나 같은 문제를 현장에서 검증할 수 있는 지역만 후보로 올린다. 인기·팀 취향·지도 검색량만으로 추가하지 않는다.

### hard gate

하나라도 실패하면 총점과 관계없이 첫 지역에서 제외한다.

- 사용자 사례 점수 1 이상
- 팀의 현장·공식 사실 검증 점수 1 이상
- 실제 콘텐츠면 특정 장소의 주소·혼자 이용·가격/무료 조건을 확인할 경로가 있음
- 행사 기간에 이동·검수·재확인이 가능함
- 안전·권리·촬영 문제가 현재 범위에서 관리 가능함

### 0~2점 rubric

| 기준 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 사용자 사례 | 관련 사건 없음 | 독립 사건 1개 | 독립 참여자 2명 이상 |
| 문제 적합 | 안내로 해결 어려움 | 일부 정보가 영향 | 행동 안내가 선택 순간과 직접 연결 |
| 혼자 수행 | 동행·최소 인원 필수 | 시간·예약 등 조건부 | 한 사람이 명확히 수행 가능 |
| 현장 검증 | 행사 전 불가 | 일부 source·현장 가능 | 주소·조건·단계를 팀이 재현 가능 |
| 콘텐츠 안정 | 핵심 조건 불명확·변동 큼 | fallback과 재확인 필요 | 공식 source와 재확인 경로 안정 |
| demo 명료성 | 가치를 짧게 설명하기 어려움 | 일부 단계만 시연 | 문제→안내→행동을 100초에 정직하게 설명 |

점수마다 `E-*`, `F-*`, `X-*` 근거 ID와 한 줄 이유를 적는다. 합계가 같으면 다음 순서로 고른다.

1. 독립 사용자 사건이 더 강함
2. 행사 전 실제 검증 가능성이 높음
3. 핵심 조건이 덜 변하고 fallback이 명확함
4. 새 외부 서비스·권리 의존성이 적음

demo 편의는 사용자 사례와 현장 검증을 이기지 않는다.

## 3단계: 퀘스트 gate D06

선택 지역 안에서도 “장소 목록”이 아니라 문제를 줄이는 행동 안내 단위를 고른다.

### hard gate

- 연결된 문제 pattern과 evidence ID가 있음
- 3~5단계가 한 사람이 순서대로 수행 가능함
- 시작 전에 혼자 이용, 시간, 비용, 예약·준비물을 설명 가능함
- 각 장소의 한국어 주소와 지도 fallback을 확인할 수 있음
- 직원에게 보여 줄 한국어 문구가 실제 상황에 맞고 과도한 약속이 아님
- 실제 콘텐츠 전체가 source·확인일·다음 확인일을 가짐
- 이미지·설명·icon 권리가 없으면 text-only fallback이 가능함
- 실패·휴무·거절 시 사용자가 안전하게 멈추거나 대체할 수 있음
- demo와 실제 정보가 한 quest에 섞이지 않음

### 0~2점 rubric

| 기준 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 사건 연결 | 가정만 있음 | 사건 한 건과 관련 | 반복 pattern의 선택 순간 해결 |
| 정보 가치 | 일반 장소 설명 | 일부 조건 확인 | 혼자 이용·행동·표현이 결정을 바꿈 |
| 단계 명료성 | 3~5단계로 쪼개기 어려움 | 도움 있으면 이해 | 도움 없이 다음 행동과 완료 기준 이해 |
| 실행 가능 | 핵심 조건 미확인 | 조건부·fallback 필요 | 팀이 전 단계 재현 |
| 사실 안정 | source 없거나 빠른 변동 | 재확인 가능 | A급 source·현장과 다음 확인일 있음 |
| 권리·문구 | 사용 불가·미검수 | text fallback·검수 예정 | 권리·한국어·일본어 검수 가능 |
| 시연 정직성 | 실제 성과로 오해 | 설명이 필요 | demo/실제·자기 확인 의미가 즉시 분명 |

hard gate 통과 후보 중 총점·근거 강도·검수 비용을 함께 본다. “재미있어 보임”은 별도 사용자 사건 없이 점수를 올리지 않는다.

## 후보 생성 workshop

인터뷰 3개 합성 시 45~60분 안에 다음 순서로 한다.

1. recorder가 사건별 `E-*`와 반대 근거 `X-*`를 읽는다.
2. 각자 해결 아이디어 없이 문제 pattern을 독립 작성한다.
3. 동일 사건을 합치고 독립 참여자 수를 센다.
4. D04 유지·수정·보류 후보를 정한다.
5. 통과한 pattern에서만 지역 후보를 최대 3개 만든다.
6. 지역 hard gate 뒤 evidence ID를 보며 점수화한다.
7. 지역 1개·예비 1개를 현장 확인 대상으로 정한다.
8. 각 지역에 quest 후보 최대 3개를 만들고 hard gate를 적용한다.
9. 확인해야 점수가 바뀌는 사실을 field checklist로 만든다.

먼저 후보 이름을 정하고 인터뷰에서 근거를 찾지 않는다. 진행자가 인터뷰를 수행한 사람이라도 점수 근거를 다른 reviewer가 질문한다.

## 현장 확인

지역·quest를 확정하기 전 가상 데이터와 실제 사실을 분리해 확인한다.

- 장소까지 실제 이동 경로와 주소 복사
- 한 명 입장·주문·체험 가능 여부와 제한 시간
- 필수 예약·최소 주문·가격·결제 조건
- 단계별 한국어 대화 필요 지점
- 실패·휴무·혼잡 시 멈춤·대안
- 지도 pin이 같은 장소를 가리키는지 iOS·Android 확인
- 사진 촬영·시설 설명 사용 가능 범위
- 확인일과 다음 재확인 시점

현장 직원·고객의 이름·얼굴·연락처·비공개 대화 원문은 저장소에 넣지 않는다. 확인할 수 없으면 `unknown`이며 편리한 값으로 추정하지 않는다.

## 반대 증거 처리

반대 사례는 후보 점수에서 빼고 숨기는 항목이 아니라 범위를 정하는 근거다.

| 반대 증거 | 가능한 판단 |
| --- | --- |
| 안내는 충분했지만 가격 때문에 포기 | 가격 문제는 제품 해결 범위 밖으로 명시 |
| 혼자 가능 정보가 있어도 동행 선호 | 모든 혼행객에게 행동 전환을 약속하지 않음 |
| 거주자에게만 문제 반복 | 타깃 수정 후보 |
| stimulus는 이해하지만 실제로 안 씀 | 행동 가치 보류, 추가 관찰 |
| 한 지역에서만 검증 불가 | 지역 교체, 문제 가설은 유지 가능 |

기존 스펙과 반대되는 증거가 나오면 evidence ID, 영향받는 화면·API·metric을 기록하고 변경 여부를 결정한다.

## 결정 규칙

### 선택

- hard gate를 모두 통과함
- 점수마다 evidence ID가 있음
- 첫 후보와 예비 후보의 차이를 설명할 수 있음
- 반대 근거·unknown·무효화 조건이 있음
- 콘텐츠 register를 채울 owner·reviewer·일정이 있음

### 조건부

현장 확인 하나로 hard gate가 결정되며 확인 담당·기한·실패 시 예비 후보가 명확하다. public 콘텐츠로는 선택하지 않고 “현장 검증 중” 상태를 유지한다.

### 보류

사용자 사건 또는 현장 검증이 0점, source·권리·혼자 수행이 불명확, 반대 사례가 핵심 가설을 무너뜨린다. 가상 demo로 바꿀 수는 있지만 실제 후보 통과로 표시하지 않는다.

## evidence 검토 질문

- 이 점수는 어떤 사건·관찰·사실 ID에서 왔는가?
- 같은 사건을 독립 사례로 두 번 세지 않았는가?
- 실제 행동인가, 미래 의향·호감인가?
- 안내가 없어서 포기했는가, 안내로 해결 못 할 제약인가?
- 특정 지역을 먼저 좋아해서 근거를 맞춘 것은 아닌가?
- 현장 사실과 사용자 문제 근거를 혼동하지 않았는가?
- 반대 사례가 사라지거나 완화된 이유가 기록됐는가?
- 선택이 틀렸다고 판단할 다음 관찰은 무엇인가?

## 개인정보·공개 범위

- 참여자 코드는 `P01` 형식만 사용한다.
- 짧은 인용도 장소·날짜·직업 조합으로 식별되지 않게 검토한다.
- 연락처·모집 채널 ID·정확한 숙소·녹음·원본 사진을 저장하지 않는다.
- 업체 담당자 개인 연락처와 비공개 답변 원문을 커밋하지 않는다.
- public 발표에서는 작은 표본 수와 반대 사례를 함께 말한다.

선택 결과는 “일본인은 모두”가 아니라 “이 표본의 독립 사건 N개에서”라고 표현한다.
