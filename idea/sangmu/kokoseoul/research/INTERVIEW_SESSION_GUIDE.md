# 사용자 인터뷰 세션 진행 가이드

작성일: 2026-11-21 · 상태: 일본어 검수 전 실행 초안

이 문서는 [일본인 사용자 검증 계획](../docs/USER_RESEARCH_v0.1.md)의 30분 인터뷰를 진행자가 같은 기준으로 실행하기 위한 체크리스트다. 질문 원문과 판단 기준은 검증 계획을 따르며, 참여자별 기록은 [인터뷰 기록 양식](interviews/TEMPLATE.md)을 사용한다.

## 역할

가능하면 두 사람이 참여한다.

| 역할 | 책임 | 피할 행동 |
| --- | --- | --- |
| 진행자 | 동의 확인, 질문, 시간 관리, 과제 제시 | 제품 설명, 답 유도, 메모에 몰입 |
| 기록자 | 사건 순서·관찰·짧은 인용 기록 | 채팅에 개인정보 복사, 질문 끼어들기 |

한 사람이 진행하면 녹음 여부와 관계없이 핵심 사건만 메모하고, 세션 종료 직후 10분 동안 기록을 보완한다. 참여자 코드 외의 이름·계정명은 노트 제목이나 파일명에 쓰지 않는다.

## 세션 15분 전

- [ ] 참여자 코드와 빈 기록 파일을 준비했다.
- [ ] 일정·시간대·온라인 URL이 확정 메시지와 같다.
- [ ] 안내 예시의 버전과 demo 여부를 기록했다.
- [ ] 일본어 모집·동의·과제 문구가 검수된 최신본이다.
- [ ] 화면 공유 알림·개인 탭·메신저·비밀번호 관리자를 닫았다.
- [ ] 온라인이면 마이크와 연결만 확인하고 자동 녹화를 껐다.
- [ ] 녹음 예정이면 저장 위치·접근자·삭제일을 다시 확인했다.
- [ ] 사례비가 있으면 지급 조건과 담당자가 확정됐다.
- [ ] 30분 뒤 다음 일정과 10분 기록 시간이 비어 있다.

안내 예시는 실제 서비스로 오해하지 않게 `검토용 예시`라고 표시한다. 참여자마다 다른 예시를 쓰면 파일명·version을 남겨 결과를 섞지 않는다.

## 시작 0~3분

먼저 일정과 언어를 확인하고 제품을 설명하기 전에 동의를 받는다.

> 本日はありがとうございます。所要時間は約30分です。ソウルで一人で場所や活動を選んだ経験について伺い、後半で検討用の案内例を見ていただきます。正解はなく、サービスへの賛成をお願いするものではありません。答えにくい質問は飛ばしても、いつでも中止しても構いません。

> お名前や連絡先は調査記録に残しません。メモを取ってもよろしいですか。

녹음이 필요할 때만 메모 동의와 분리해 묻는다.

> 内容を正確に確認するため録音してもよろしいですか。録音は{保存場所の説明}に保存し、アクセスできるのは{役割}だけです。{削除日}までに削除します。録音に同意しなくてもインタビューには参加できます。

메모에 동의하지 않으면 세션 기록을 만들지 말고 진행 여부를 다시 확인한다. 녹음을 거절하면 녹음 기능이 꺼진 것을 확인한 뒤 메모만 사용한다. 동의 상태를 추측하거나 모집 단계 답변으로 대신하지 않는다.

## 실제 사건 3~15분

가장 최근 사건 하나를 시간순으로 복원한다. 추상적인 답이 나오면 일반 의견을 반박하지 말고 사건으로 돌아간다.

### 기본 순서

1. 언제·어떤 상황에서 혼자 무엇을 하려 했는지
2. 아이디어를 어디서 얻었는지
3. 실제로 확인한 정보와 사용한 정보원
4. 결정을 바꾸거나 확정한 순간
5. 결국 한 행동과 든 시간·비용
6. 당시 결정에 도움이 됐거나 부족했던 정보

### 사건으로 돌아오는 일본어 문구

> 一般的な意見ではなく、最近実際にあった一回のことについて、もう少し教えていただけますか。

> その時、次に実際に何をしましたか。

> それを知ったのは、決める前ですか、決めた後ですか。

> 覚えている範囲で大丈夫です。分からない場合は「分からない」と答えてください。

참여자가 검색 기록이나 화면을 보여주면 개인 메시지·계정·예약번호가 보이지 않게 참여자가 직접 범위를 선택하게 한다. 진행자가 화면을 캡처하거나 링크를 저장하지 않는다. 필요한 것은 정보원의 종류와 의사결정에 쓴 항목이지 계정 원문이 아니다.

## 안내 예시 관찰 15~25분

과거 사건 질문이 끝났다고 말한 뒤 예시를 보여 준다. 먼저 기능과 정답을 설명하지 않는다.

> ここからは検討用の案内例を見ていただきます。完成したサービスではありません。私が説明する前に、分かることと次にすることを声に出して教えてください。

다음 순서로 한 번씩 요청한다.

1. 무엇을 할 수 있는 안내인지 설명
2. 혼자 지금 시작할지 결정하고 근거 말하기
3. 다음 행동 찾기
4. 한국어 요청 카드 의미 설명
5. 불안하거나 더 확인할 정보 표시

진행자는 성공 여부를 표정이나 칭찬으로 알려주지 않는다. `ありがとうございます`, `分かりました`처럼 중립적으로 반응한다.

### 참여자가 멈췄을 때

5초 이상 기다린 뒤 아래 순서로만 돕는다. 어느 단계에서 도움을 줬는지 기록한다.

1. `今、どこを見ていますか。`
2. `何が起こると思いましたか。`
3. `次にできそうなことはありますか。`
4. 마지막에만 과제 의도를 설명하고 도움 후 이해를 따로 기록

화면 오류나 번역 오류로 과제를 수행할 수 없으면 참여자 실패로 기록하지 않는다. `prototype_issue`로 표시하고 해당 관찰을 성공률 분모에서 분리한다.

## 마무리 25~30분

예시가 실제 사건의 선택을 바꿀지와 여전히 막는 조건을 모두 묻는다.

> この案内があっても始めないとしたら、どのような理由がありますか。

기능 요청이 나오면 바로 약속하지 않고 관련 사건을 확인한다.

> その機能が必要だと思った、最近の具体的な場面はありますか。

종료 전에 다음을 알린다.

- 익명화한 메모 사용 방식
- 녹음했다면 삭제일
- 사례비가 있다면 지급 절차
- 후속 연락은 별도 동의를 받은 경우에만 한다는 점

소개를 부탁할 때 참여자의 연락처를 받지 않는다. 모집 안내를 당사자에게 전달해 달라고만 요청한다.

## 종료 직후 10분

참여자가 퇴장한 뒤 진행자와 기록자가 독립적으로 2분씩 메모한 다음 비교한다. 먼저 합의하면 반대 관찰이 사라질 수 있다.

- [ ] 실제 사건의 시작·결정 변화·대체 행동이 시간순으로 있다.
- [ ] 참여자 말과 진행자 해석이 분리돼 있다.
- [ ] 포기하지 않은 사례나 가설 반대 증거가 있다.
- [ ] 도움 없이 한 행동과 도움 후 행동이 분리돼 있다.
- [ ] 기능 요청이 연결된 실제 사건이 있는지 표시했다.
- [ ] 이름·연락처·계정·정확한 주소를 제거했다.
- [ ] 짧은 인용이 없어도 의미가 유지되면 요약으로 바꿨다.
- [ ] 다음 인터뷰에서 확인할 질문을 하나만 선정했다.
- [ ] 녹음 삭제일을 저장소 밖 관리 목록에 남겼다.

세션 하나만으로 타깃·지역·퀘스트를 확정하지 않는다. 긴급한 안전·사실 오류가 아니라면 인터뷰 3개 전에는 질문 대본을 크게 바꾸지 않고, 바꿀 경우 변경 시점과 이유를 합성 문서에 남긴다.

## 중단과 제외 기준

다음 경우 즉시 또는 해당 과제를 중단한다.

| 상황 | 행동 |
| --- | --- |
| 참여자가 중단 요청 | 이유를 묻지 않고 종료, 미사용 요청 시 메모 폐기 |
| 제3자의 개인정보가 화면에 노출 | 화면 공유 중단, 기록하지 않음 |
| 감정적 불편이 커짐 | 질문 중단, 계속 여부를 참여자가 선택 |
| 대상 경험이 없음 | 짧게 종료하거나 안내 이해 테스트로 별도 구분 |
| 진행자가 답을 설명함 | 해당 과제는 도움 후 관찰로 표시 |
| 예시 자체가 깨짐 | 과제 중단, prototype issue로 기록 |

안내 이해 테스트만 한 참여자는 문제 사례 수에 포함하지 않는다. 중단한 세션도 사용 가능한 범위와 동의가 명확할 때만 기록하며, 인원 수를 채우기 위해 불완전한 사례를 반복 근거로 세지 않는다.
