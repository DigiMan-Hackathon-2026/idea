# 일본어 검수 시트

작성일: 2026-11-22 · 상태: 검수 전

일본인 사용자가 읽는 모든 일본어 문장을 모어 화자가 검수하기 위한 시트다. [japanese-review-sheet.csv](japanese-review-sheet.csv)를 노션이나 스프레드시트로 가져가 위에서부터 검수한다. 검수자는 [일본어 문구 검수 기준](../../../docs/JAPANESE_COPY_REVIEW_v0.1.md)과 [여기서울 UX 원칙](../../../docs/UX_PRINCIPLES_v0.1.md)을 함께 본다.

## 검수 순서

| priority | 묶음 | 대상 | 이유 |
| ---: | --- | --- | --- |
| 1 | 앱 퀘스트, 앱 퀘스트 목록 | 앱에 들어간 퀘스트의 제목·요약·본문·단계·완료 버튼·요청 문장 뜻, 목록 카드 문구 | 2026-11-29 시연에서 그대로 읽힌다 |
| 2 | 앱 화면 | 버튼·안내·오류·빈 화면 등 공통 화면 문구 | 모든 퀘스트에서 보인다 |
| 3 | 퀘스트 초안 | 아직 앱에 없는 초안의 단계 안내와 요청 문장 뜻 | 앱에 옮기기 전에 고친다 |
| 4 | 역 카드 | 역명 유래 카드의 제목·발음·한자 풀이·이야기·보충 설명 | 수가 많아 마지막에 본다 |

시간이 부족하면 priority 1만 끝내도 시연 문구는 검수된다.

## 열

| 열 | 뜻 |
| --- | --- |
| `id` | 줄 번호(J0001~). 시트를 다시 만들면 바뀐다 |
| `file`, `locator` | 문구가 있는 파일과 위치. JSON은 키 경로, 코드와 초안은 줄 번호 |
| `context` | 문구가 쓰이는 자리(단계 완료 버튼, 오류 안내 등) |
| `ko` | 같은 자리의 한국어. 요청 문장 줄에서는 직원에게 보여 줄 한국어 문장 |
| `ja` | 검수할 일본어 |
| `review` | `ok`, `fix`, `question` 중 하나 |
| `suggested_ja` | `fix`일 때 고친 일본어 |
| `reviewer_code` | 검수자 코드(JR01 등). 이름은 쓰지 않는다 |
| `note` | 이유, 질문, 뜻이 바뀐 수정이면 그 내용 |

## 볼 것

- 자연스러운가: 번역투, 어색한 조사·어순, 너무 딱딱하거나 가벼운 표현
- 뜻이 같은가: 한국어와 정보·조건·행동이 같은지. 일본어에만 있거나 빠진 정보가 없는지
- 요청 문장 뜻: `ko`의 한국어 문장을 직원이 읽었을 때와 일본어 뜻이 같은지. 한국어 문장 자체가 어색하면 `note`에 적는다
- 버튼·완료 문구: 누른 뒤 무슨 일이 일어나는지 예측되는지
- 장소·고유명사: 한국어 이름의 가타카나 표기가 실제 발음에 가까운지, 같은 장소를 문서마다 같게 쓰는지
- 사실 표현: 확인되지 않은 것을 단정하지 않는지(예: "〜できます" 대신 "〜できるか確認してください")

## 표기 방침

- 퀘스트·화면 문구: です・ます체
- 역 카드: だ체(나중에 바꿀 수 있다)
- 한국 지명·상호: 한자나 일본어 이름 뒤에 한국어 발음을 가타카나로 덧붙인다. 예: 聖水（ソンス）
- 역 카드의 일본 관련 역사 용어: 日本統治時代, 光復（解放）, 韓日併合（韓国併合）, 壬辰倭乱（文禄・慶長の役）, 倭軍（日本軍）. 사실은 원문대로 두고 표현의 자연스러움만 본다

## 반영

- 시트를 다시 만들 때: `python3 scripts/build_japanese_review_sheet.py`. 검수 열은 비어서 다시 생성되므로, 검수 중인 시트는 덮어쓰지 말고 별도 사본에 기록한다.
- 앱 퀘스트·앱 화면(`src/`)의 `fix`는 앱 담당이 반영한다. 퀘스트 초안과 역 카드(`research/`)는 데스크 리서치 담당이 반영한다.
- 반영한 뒤 초안과 카드의 검수 상태(`review.japanese` 등)를 바꾸고, 검수자 코드와 검수일을 남긴다.
