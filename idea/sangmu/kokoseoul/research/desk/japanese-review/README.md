# 일본어 검수 시트

작성일: 2026-11-22 · 상태: 검수 전

일본인 사용자가 읽는 모든 일본어 문장을 모어 화자가 검수하기 위한 시트다. [japanese-review-sheet.csv](japanese-review-sheet.csv)를 노션이나 스프레드시트로 가져가 위에서부터 검수한다. 검수자는 [일본어 문구 검수 기준](../../../docs/JAPANESE_COPY_REVIEW_v0.1.md)과 [여기서울 UX 원칙](../../../docs/UX_PRINCIPLES_v0.1.md)을 함께 본다.

## 검수 순서

| priority | 묶음 | 대상 | 이유 |
| ---: | --- | --- | --- |
| 1 | 앱 퀘스트, 앱 퀘스트 목록 | 앱에 들어간 퀘스트의 제목·요약·본문·단계·완료 버튼·요청 문장 뜻, 목록 카드 문구 | 2026-11-29 시연에서 그대로 읽힌다 |
| 2 | 앱 화면, 앱 데모·선택지, 지하철 역명 | 버튼·안내·오류·빈 화면 등 공통 화면 문구(`{ ja, ko }` 객체와 `[일본어, 한국어]` 쌍 포함), 필터 선택지 라벨, 가상 데모 퀘스트 문구, 서버 오류 메시지, 지하철 안내의 1~9호선 역 이름 | 모든 퀘스트와 지하철 안내에서 보인다 |
| 3 | 퀘스트 초안 | 아직 앱에 없는 초안의 단계 안내와 요청 문장 뜻 | 앱에 옮기기 전에 고친다 |
| 4 | 역 카드 | 역명 유래 카드의 제목·발음·한자 풀이·이야기·보충 설명 | 수가 많아 마지막에 본다 |

시간이 부족하면 priority 1만 끝내도 시연 문구는 검수된다.

## 1순위 묶음

[japanese-review-first-pass.csv](japanese-review-first-pass.csv)는 사용자가 가장 먼저 읽는 문구만 모은 묶음이다. 전체 시트와 `id`가 같으므로 검수 결과를 그대로 옮길 수 있다. 처음 검수는 이 묶음부터 한다.

- 앱 퀘스트 목록 카드 문구 전부
- 퀘스트·방문 가이드의 제목, 요약, 장소 이름, 직원에게 보여 줄 문장의 일본어 뜻
- 홈, 헤더, 언어 전환, 온보딩, 필터, 퀘스트 카드·결과·상세, 오류·없는 페이지 화면
- 지하철 안내의 방향 확인·반대 방향 복구·역무원 문장 화면, 가까운 역 찾기
- 역 앨범과 스탬프 받기·저장 화면

단계별 안내 본문, 지하철 현장 안내(층·출구·엘리베이터), 역 이름, 역 카드는 전체 시트에서 이어서 본다.

## 열

| 열 | 뜻 |
| --- | --- |
| `id` | 줄 번호(J0001~). 시트를 다시 만들면 바뀐다 |
| `file`, `locator` | 문구가 있는 파일과 위치. JSON은 키 경로, 코드와 초안은 줄 번호 |
| `context` | 문구가 쓰이는 자리(단계 완료 버튼, 오류 안내 등) |
| `ko` | 같은 자리의 한국어. 요청 문장 줄에서는 직원에게 보여 줄 한국어 문장. 서버 오류 메시지처럼 일본어만 있는 문구는 비어 있다 |
| `ja` | 검수할 일본어 |
| `review` | `ok`, `fix`, `question` 중 하나 |
| `suggested_ja` | `fix`일 때 고친 일본어 |
| `reviewer_code` | 검수자 코드(JR01 등). 이름은 쓰지 않는다 |
| `note` | 이유, 질문, 뜻이 바뀐 수정이면 그 내용 |

## 볼 것

- 자연스러운가: 번역투, 어색한 조사·어순, 너무 딱딱하거나 가벼운 표현
- 뜻이 같은가: 한국어와 정보·조건·행동이 같은지. 일본어에만 있거나 빠진 정보가 없는지
- 요청 문장 뜻: `ko`의 한국어 문장을 직원이 읽었을 때와 일본어 뜻이 같은지. 한국어 문장 자체가 어색하면 `note`에 적는다
- 버튼·완료 문구: 누른 뒤 무슨 일이 일어나는지 예측되는지
- 장소·고유명사: 한국어 이름의 가타카나 표기가 실제 발음에 가까운지, 같은 장소를 문서마다 같게 쓰는지
- 사실 표현: 확인되지 않은 것을 단정하지 않는지(예: "〜できます" 대신 "〜できるか確認してください")

## 표기 방침

- 퀘스트·화면 문구: です・ます체
- 역 카드: だ체(나중에 바꿀 수 있다)
- 지하철 역명: 같은 역이 노선마다 다르게 적혀 있다. 2·3호선은 한자(市庁, 新道林), 나머지 노선은 가타카나(シチョン, シンドリム)라서 환승역 26곳의 표기가 노선마다 다르다(2026-11-22 기준). 가산디지털단지 1호선 표기에는 가운뎃점 대신 `·`(U+00B7)가 들어가 있다. 표기 방식을 하나로 정한 뒤 검수한다.
- 한국 지명·상호: 한자나 일본어 이름 뒤에 한국어 발음을 가타카나로 덧붙인다. 예: 聖水（ソンス）
- 역 카드의 일본 관련 역사 용어: 日本統治時代, 光復（解放）, 韓日併合（韓国併合）, 壬辰倭乱（文禄・慶長の役）, 倭軍（日本軍）. 사실은 원문대로 두고 표현의 자연스러움만 본다

## 한·일 불일치 점검

모어 화자 검수 전에 `python3 scripts/check_ko_ja_consistency.py`로 한국어와 일본어의 숫자·요일이 어긋난 줄을 찾는다. 대상은 시트와 같은 앱 퀘스트·방문 가이드·화면 문구·선택지·초안이다. 시간, 가격, 출구 번호, 층, 나이, 연도, 사람 수와 요일을 비교한다. 어긋난 줄이 있으면 출력하고 종료 코드 1을 돌려준다. 출력은 확인할 후보이고 오류 확정이 아니다.

- 한국어 고유어 수사(`두 명`, `세 마을`, `하나`, `혼자`)와 일본어 한자 수(`二体`, `一つ`, `両日`)는 숫자로 바꿔 비교한다.
- 한쪽에만 있는 숫자가 1뿐이면 표현 차이로 보고 넘어간다(`책 한 권 찾기`와 `本を見つける`).
- 요일은 `수요일`·`水曜`, `수·금·일`·`水・金・日曜`, `화~일`·`火〜日曜`, `(수)`·`（水）` 꼴만 센다. 料金·今日의 한자는 요일로 보지 않는다.
- 역 카드는 일본어 제목·이야기에 숫자로 쓴 값이 서울교통공사 원문에 있는지 본다. `factChecksKo`에 정정 근거가 있는 숫자(동묘앞 1739년, 을지로 1914년)와 원문의 두 자리 연도를 풀어 쓴 값(`"98.`→1998년)은 통과한다.

2026-11-22 기준 0건이다. 이전 점검에서 나온 65건은 모두 고유어 수사, 요일이 아닌 한자, 초안의 지도 링크 줄 짝짓기 같은 오탐이었다. 생성기는 지도 링크 줄을 한국어 문장으로 짝짓지 않게 고쳤고, 한국어 문장과 일본어 번역이 한 줄에 있으면 나눠서 넣는다.

## 반영

- 시트를 다시 만들 때: `python3 scripts/build_japanese_review_sheet.py`. 전체 시트와 1순위 묶음을 함께 다시 만든다. 검수 열은 비어서 다시 생성되므로, 검수 중인 시트는 덮어쓰지 말고 별도 사본에 기록한다. 앱 퀘스트(`src/modules/content/*.json`)와 방문 가이드(`src/modules/content/visit-guides/*.json`)는 자동으로 들어간다. 파일 이름이나 `slug`가 같은 초안은 앱 문구로 검수하므로 초안 묶음에서 빠진다.
- 앱 퀘스트·앱 화면(`src/`)의 `fix`는 앱 담당이 반영한다. 퀘스트 초안과 역 카드(`research/`)는 데스크 리서치 담당이 반영한다.
- 반영한 뒤 초안과 카드의 검수 상태(`review.japanese` 등)를 바꾸고, 검수자 코드와 검수일을 남긴다.
