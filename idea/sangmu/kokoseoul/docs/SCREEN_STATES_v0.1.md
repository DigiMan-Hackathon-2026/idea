# B2C 화면 상태와 일본어 문구 계약 v0.1

작성일: 2026-11-21 · 상태: 일본어 검수 전 구현 초안

이 계약은 B2C 모바일 웹의 각 경로가 어떤 서버 상태를 표시하고 어떤 행동을 허용하는지 정의한다. 일본어 문구는 기능 구현용 초안이며 실제 공개 전에 일본어 모어 화자의 검수를 받는다.

일본어·한국어 `lang`, KST·KRW·숫자·누락 fallback은 [locale·표시 형식 계약](LOCALIZATION_FORMATTING_v0.1.md)을 따른다.

용어, 위험도, 상태와 검수 결과 기록은 [일본어 문구 검수 절차](JAPANESE_COPY_REVIEW_v0.1.md)를 따른다.

## 공통 화면 원칙

- 사용자가 선택하지 않은 조건이나 진행 상태를 화면이 추측해 바꾸지 않는다.
- 로딩 중에는 기존 정보와 입력을 유지하고 중복 변경 버튼을 비활성화한다.
- 성공 여부가 불명확한 변경 요청은 성공 또는 실패를 추측하지 않고 서버 상태를 다시 조회한다.
- 오류 메시지는 다음 행동을 함께 제공하되 복구할 수 없는 기록을 복구한다고 약속하지 않는다.
- demo 콘텐츠와 실제 콘텐츠를 모든 관련 화면에서 구분한다.
- 위치 권한, 지도 앱과 계정이 없어도 주소로 핵심 흐름을 진행할 수 있다.
- 버튼 문구는 행동을 나타내며 “확인” 같은 모호한 단어만 사용하지 않는다.

## 공통 레이아웃

모바일 폭 360px을 최소 기준으로 하고 한 열 구조를 사용한다.

```text
상단: 서비스 이름 · 나의 기록
본문: 현재 화면 제목과 핵심 정보
상태: demo·이용 중지·오류 안내
행동: 현재 단계의 주요 버튼 하나
보조: 주소 복사·신고·뒤로 가기
```

고정 하단 버튼을 사용할 경우 키보드와 브라우저 하단 UI에 가리지 않게 safe area를 적용한다. 본문 마지막 요소가 버튼 뒤에 숨지 않아야 한다.

## 시작 화면 `/`

### 목적

서비스 가치를 짧게 설명하고 지역·관심사·최대 시간 조건으로 탐색을 시작한다. 세션이나 위치 권한을 만들지 않는다.

### 표시

- 제목: `ソウルで、一人でも新しい体験を。`
- 설명: `行き方だけでなく、何をすればよいかを日本語で案内します。`
- 지역: 기본 전체
- 관심사: 선택 사항, 최대 5개
- 최대 시간: 제한 없음 또는 15~240분 선택
- 주요 버튼: `クエストを探す`

### 행동

- 조건은 URL query로 이동해 뒤로 가기와 링크 복사가 가능해야 한다.
- 관심사를 선택하지 않아도 탐색할 수 있다.
- “내 위치”를 기본값으로 요청하지 않는다.

### 검수

- 쿠키가 없는 상태에서 렌더링해도 세션 API를 호출하지 않는다.
- 모든 입력에 화면 label이 있고 키보드로 선택할 수 있다.
- 주요 버튼 이름에 목적지가 드러난다.

연결 AC: AC01, AC18

## 탐색 화면 `/quests`

### 기본 상태

- 적용 조건과 조건 변경 행동
- 추천 3개와 나머지 목록
- 카드의 제목, 지역, 시간, 비용, 혼자 이용 조건, 추천 이유
- demo 배지

추천 영역은 후보가 3개보다 적으면 있는 항목만 표시한다. 추천과 일반 목록에 같은 퀘스트를 중복 표시하지 않는다.

### 로딩

- 조건 영역은 유지한다.
- 카드와 비슷한 높이의 placeholder를 표시한다.
- 이전 조건의 결과를 새 조건 결과처럼 표시하지 않는다.

### 결과 없음

- 제목: `条件に合うクエストが見つかりませんでした`
- 설명: `選んだ条件を確認するか、条件を減らしてもう一度探してください。`
- 선택한 조건을 그대로 표시한다.
- 버튼: `条件を変更する`
- 완료 기록이 있으면 보조 링크: `完了した記録を見る`

조건을 자동으로 해제하거나 완료 퀘스트를 몰래 다시 넣지 않는다.

### 네트워크 오류

- 제목: `クエストを読み込めませんでした`
- 버튼: `もう一度試す`
- 조건 입력과 URL을 유지한다.

### 검수

- 추천 이유가 실제 `matchReasons`와 일치한다.
- 비용 미확인을 0원으로 표시하지 않는다.
- 카드 전체를 링크로 만들더라도 내부 보조 버튼과 중첩 interactive element를 만들지 않는다.

연결 AC: AC01, AC02, AC18, AC19

## 상세 화면 `/quests/:questId`

### 기본 상태

- 제목·요약·상세 일본어
- 예상 시간·비용·지역·관심사
- 혼자 이용 조건과 정보 확인일
- 단계 개요
- demo 표시
- 시작·이어하기·완료 기록 보기 중 서버가 허용한 주요 행동 하나
- 정보 오류 신고

### 주요 행동 결정

| 서버 상태 | 주요 버튼 |
| --- | --- |
| `canStart: true`, ownRunId null | `このクエストを始める` |
| own run in progress | `続きから始める` |
| own run completed | `完了した記録を見る` |
| paused·archived, own run 없음 | 버튼 없음, 목록으로 이동 |

클라이언트가 status를 조합해 판단하지 않고 서버의 `canStart`, `ownRunId`, availability를 사용한다.

### 시작 전 기록 안내

시작 버튼 뒤 modal 또는 별도 panel에서 다음을 안내한다.

- 제목: `進行記録について`
- 본문: `進行記録はこのブラウザに30日間保存され、他の端末とは共有されません。ブラウザのデータを削除すると記録を確認できなくなる場合があります。`
- 주요 버튼: `記録を作成して始める`
- 취소: `戻る`

동의 전에는 visitor session을 만들지 않는다. 기존 유효 세션이면 같은 안내 뒤 기존 세션을 재사용한다.

### 중지·보관

- paused 제목: `現在このクエストは利用できません`
- 서버의 `unavailableReasonJa` 표시
- 보관 제목: `このクエストは終了しました`
- 본인 run이 있으면 기록 읽기 링크 유지
- 신규 시작 버튼 제거

### 찾을 수 없음

미공개, 없는 ID, 공개 이력 없는 draft는 같은 화면을 사용한다.

- 제목: `クエストが見つかりません`
- 버튼: `クエスト一覧に戻る`

연결 AC: AC01, AC06~AC08, AC10, AC14, AC19

## 진행 화면 `/runs/:runId`

### 기본 상태

- 고정 버전 제목과 demo 표시
- 전체 단계 수와 현재 위치
- 현재 단계 일본어 행동 안내
- 장소명·한국어 주소·정보 확인일
- 지도 열기와 주소 복사
- 한국어 요청 카드와 일본어 뜻
- 자기 확인 완료 버튼
- 정보 오류 신고

완료 버튼 문구는 단계의 행동을 반영한다. 공통 fallback은 `このステップを完了する`다. 버튼 주변에 `実際の訪問や出席を証明するものではありません。`를 항상 반복하지 않고 첫 단계 안내 또는 도움말에서 명확히 설명한다.

### 단계 잠금

- 완료한 단계는 다시 열어볼 수 있다.
- 다음 미완료 단계만 완료 버튼이 활성화된다.
- 이후 단계는 제목 또는 순서만 보여주고 완료 행동을 제공하지 않는다.
- 클라이언트 잠금과 관계없이 서버가 순서를 다시 검사한다.

### 완료 요청 중

- 완료 버튼을 비활성화하고 `保存しています…` 표시
- 현재 단계와 입력을 유지
- 다른 navigation을 강제로 막지 않되 중복 요청은 보내지 않음

### 응답 유실

- 제목: `進行状況を確認しています`
- `GET /runs/:runId`로 현재 상태 조회
- 해당 단계가 완료됐으면 다음 단계 또는 완료 화면으로 이동
- 완료되지 않았고 장애가 끝났으면 재시도 버튼 제공

### 콘텐츠 중지

- 현재까지 완료한 단계와 안내는 읽을 수 있다.
- 미완료 단계 버튼을 비활성화한다.
- 서버의 일본어 중지 사유 표시
- 버튼: `クエスト一覧に戻る`

### 지도 실패

URL 생성·외부 이동·주소 copy·위치 권한 없음과 실제 기기 검수는 [지도·주소 전달 계약](MAP_ADDRESS_HANDOFF_v0.1.md)을 따른다.

- 지도 링크 실패를 단계 실패로 처리하지 않는다.
- 한국어 주소를 선택 가능한 text로 표시한다.
- 복사 버튼 실패 시 수동 복사 안내를 표시한다.

### 권한 없음·세션 만료

타인의 run과 없는 ID는 같은 찾을 수 없음 화면이다. 세션 만료는 별도 안내한다.

- 제목: `進行記録を確認できません`
- 설명: `記録の有効期限が切れているか、このブラウザに記録がありません。`
- 버튼: `クエスト一覧に戻る`

과거 기록 복구나 다른 기기 동기화를 약속하지 않는다.

연결 AC: AC03~AC10, AC16~AC19

## 완료 화면 `/runs/:runId/completion`

### 표시

- `クエスト完了`
- 퀘스트 제목과 완료 날짜
- stamp label
- demo 표시
- 기쁨 점수 1~5
- 새 경험 여부 선택 질문
- 선택 comment
- 나의 기록 링크

완료 카드는 P0에서 공개 공유 URL이나 생성 이미지가 아니다. 현재 서버 기록을 화면에 재구성한다.

### 피드백

- 질문: `この体験はどのくらい楽しかったですか。`
- 새 경험: `ソウルで新しい体験ができましたか。`
- comment label: `よかった点や分かりにくかった点（任意）`
- 민감정보 안내: `個人情報は入力しないでください。`
- 저장: `フィードバックを保存する`
- 저장 완료: `フィードバックを保存しました`

점수는 radio group으로 구현하고 색·emoji만으로 선택 상태를 구분하지 않는다.

### 미완료 접근

409 `RUN_NOT_COMPLETED`이면 진행 화면으로 돌아가는 버튼을 표시한다. 화면이 완료 상태를 추측해 stamp를 만들지 않는다.

연결 AC: AC09~AC12, AC18, AC19

## 나의 기록 `/my`

### 표시

- 진행 중과 완료 tab 또는 heading
- 각 항목의 제목, 시작·완료 날짜, 현재 단계, 이용 가능 여부
- 실제 세션 `expiresAt`
- 전체 기록 삭제

### 빈 상태

- 제목: `まだ記録がありません`
- 설명: `クエストを始めると、このブラウザで続きから再開できます。`
- 버튼: `クエストを探す`

### 삭제 확인

- 제목: `このブラウザの記録を削除しますか。`
- 설명: `進行中と完了済みの記録、フィードバックが削除され、元に戻せません。`
- 파괴 행동: `すべての記録を削除する`
- 취소: `キャンセル`

삭제 요청 중 dialog를 닫거나 중복 제출하지 못하게 한다. 204 성공 뒤 쿠키와 화면 상태를 제거한다. 실패하면 기존 기록을 유지하고 재시도 행동을 제공한다.

연결 AC: AC06, AC10, AC16, AC18

## 정보 오류 신고

상세와 진행 화면에서 같은 panel을 사용한다.

### 필드

- category: `情報が違う`, `利用できない`, `その他`
- comment: 최대 500자
- 민감정보 안내
- 제출: `報告を送信する`

처음 신고할 때 visitor session이 없으면 기록 안내 후 세션을 만든다. `clientRequestId`는 panel을 열 때가 아니라 실제 제출 의도가 생긴 요청 단위로 만들고, 응답 유실 재시도에서는 같은 ID를 사용한다.

### 성공

- `報告を受け付けました。確認にご協力いただきありがとうございます。`
- 같은 멱등 요청의 200도 같은 성공 화면

### 같은 ID·다른 본문

`REQUEST_CONFLICT`이면 새 ID로 자동 제출하지 않는다. 현재 입력을 유지하고 사용자가 다시 보내기를 선택할 때 새 요청 ID를 만든다.

연결 AC: AC05, AC16

## 전역 오류 매핑

pending·응답 유실·idempotency key·revision과 자동 재시도 금지는 [클라이언트 요청·복구 계약](CLIENT_RECOVERY_v0.1.md)을 따른다.

| API code | 화면 행동 |
| --- | --- |
| VALIDATION_ERROR | 해당 입력 근처 일본어 오류와 summary |
| SESSION_REQUIRED | 세션 만료·기록 없음 화면 |
| ORIGIN_FORBIDDEN | 입력 유지, 현재 공식 화면을 다시 연 뒤에도 반복되면 request ID 안내 |
| QUEST_UNAVAILABLE | 중지 사유와 목록 이동 |
| STEP_ORDER_CONFLICT | run 재조회 후 현재 단계 표시 |
| REQUEST_CONFLICT | 입력 유지, 명시적 새 제출 제공 |
| RUN_NOT_COMPLETED | 진행 화면 이동 |
| NOT_FOUND | 동일한 찾을 수 없음 화면 |
| RATE_LIMITED | 서버 재시도 시각 안내, 자동 연타 금지 |
| SERVICE_UNAVAILABLE | 입력 유지, 제한된 재시도 |

운영자 전용 `ADMIN_FORBIDDEN`, `VERSION_CONFLICT`는 B2C 화면에 노출하지 않는다.

## 접근성 검수

화면별 keyboard·screen reader·focus·확대 검수와 증거는 [모바일 접근성 구현·검수](ACCESSIBILITY_VERIFICATION_v0.1.md)를 따른다.

- heading 순서가 화면 구조와 일치한다.
- 모든 입력에 programmatic label과 오류 연결이 있다.
- 주요 행동과 보조 행동의 focus 순서가 시각 순서와 일치한다.
- 상태 변화는 `aria-live`를 필요한 범위에서만 사용한다.
- dialog는 제목, focus 이동, 닫기, focus 복귀를 제공한다.
- 터치 영역은 최소 44px이며 인접 행동 사이에 충분한 간격이 있다.
- 색 외에 text·icon·shape로 상태를 구분한다.
- 200% 확대와 360px 폭에서 가로 스크롤 없이 주요 행동을 사용할 수 있다.
- skeleton과 animation은 `prefers-reduced-motion`을 존중한다.
- 한국어 요청 카드는 일본어 뜻과 언어 label을 함께 표시한다.

## 화면 계약 변경 규칙

필드·상태·주요 버튼을 바꾸면 B2C 스펙, API 예시, 화면 fixture와 관련 AC를 같은 기능 단위에서 갱신한다. 일본어 검수 결과 의미가 달라지면 단순 copy 수정으로 처리하지 않고 관련 행동과 오류 매핑을 다시 확인한다.
