# 일본어 문구 검수 절차 v0.1

작성일: 2026-11-21 · 상태: 검수자 배정 전 작업 기준

이 문서는 모집·인터뷰·저충실도 자극물·제품 화면·퀘스트 콘텐츠의 일본어 초안을 같은 기준으로 검수하고, 언어 자연스러움과 제품 동작 의미를 함께 보존하기 위한 절차다. 이 문서의 일본어 용어도 확정 번역이 아니라 모어 화자와 확인할 작업 용어다.

## 검수 목표

- 일본어가 자연스러운지만 아니라 사용자가 다음 행동과 결과를 정확히 이해한다.
- demo, 자기 확인 완료, 30일 보존, 다른 기기 복구 불가를 과장 없이 전달한다.
- 한국어 요청 카드가 실제 한국어와 같은 의도·존댓말 수준을 가진다.
- 버튼·오류·콘텐츠에서 같은 개념을 불필요하게 다른 말로 부르지 않는다.
- 번역 수정이 상태 전이·API 의미를 바꾸면 제품 계약 변경으로 다룬다.

## 검수 대상과 우선순위

| 우선 | 대상 | 이유 | 원본 |
| ---: | --- | --- | --- |
| P0 | 삭제·세션·중지·복구 불가·demo·완료 의미 | 손실 또는 실제 이용 오해 방지 | [화면 상태 계약](SCREEN_STATES_v0.1.md) |
| P0 | 모집 동의·중단·녹음·개인정보 | 참여 동의의 정확성 | [모집 문안](../research/RECRUITMENT_MESSAGES.md), [세션 가이드](../research/INTERVIEW_SESSION_GUIDE.md) |
| P0 | 한국어 요청 카드와 일본어 뜻 | 현장 의사소통 오류 방지 | quest 후보와 콘텐츠 register |
| P1 | 시작·이어하기·단계 완료·신고 오류 | 행동과 서버 상태 일치 | 화면 상태 계약 |
| P1 | 안내 자극물 | 사용자 조사 해석 가능성 | [가상 안내 예시](../research/stimuli/TEXT_GUIDANCE_DEMO_v0.1.md) |
| P2 | 가치 설명·추천 이유·완료 축하 | 이해와 톤 | 화면·quest 콘텐츠 |

P0가 미검수면 해당 모집·사용자 데이터 수집·실제 콘텐츠 공개를 진행하지 않는다. demo 발표만 하더라도 demo와 실제 방문 미인증 문구는 P0다.

## 검수자 조건

### 일반 일본어

- 일본어 모어 화자
- 대상 사용자와 비슷한 모바일 서비스 문맥을 이해함
- 제품 설명을 듣기 전에 화면만 보고 행동을 설명할 수 있음

### 한국어 요청 카드

- 한국어 의도·존댓말과 일본어 설명을 모두 확인할 수 있는 사람
- 한 사람이 두 언어를 충분히 검수하기 어렵다면 한국어 검수자와 일본어 검수자가 각각 확인
- 음식 알레르기·의료·법률·안전 표현은 일반 언어 검수만으로 공개하지 않음

저장소에는 `JR01`, `KR01` 같은 검수자 코드만 남긴다. 실명·연락처·계정·보상 정보는 별도 채널에서 관리한다.

## 작업 용어표

아래는 일관성 확인을 위한 첫 후보이며 검수 결과로 바꿀 수 있다.

| 한국어 개념 | 일본어 작업 용어 | 사용 원칙과 확인 질문 |
| --- | --- | --- |
| 퀘스트 | クエスト | 대상 사용자에게 game 과제로만 오해되지 않는지 확인 |
| 가상 데모 | デモ体験 | 실제 예약·방문 가능한 콘텐츠로 보이지 않아야 함 |
| 진행 기록 | 進行記録 | 방문 인증·공식 출석 기록처럼 보이지 않아야 함 |
| 시작 | 始める | 기록 생성 전에는 `記録を作成して始める`처럼 결과 명시 |
| 이어하기 | 続きから始める | 새 run 생성처럼 보이지 않는지 확인 |
| 단계 | ステップ | 행동 순서 의미로 일관 사용 |
| 단계 완료 | このステップを完了する | 실제 방문 증명이 아닌 자기 확인임을 주변 안내에서 명시 |
| 완료 기록 | 完了した記録 | achievement·방문 인증으로 과장되지 않게 사용 |
| 정보 확인일 | 情報確認日 | 영업 보장일이나 업데이트일과 혼동하지 않게 함 |
| 혼자 이용 확인 | 一人で利用できることを確認済み | 확인 범위와 날짜가 가까이 있어야 함 |
| 혼자 이용 미확인 | 一人で利用できるか未確認です | 가능하다는 암시 금지 |
| 정보 오류 신고 | 情報の誤りを報告 | 고객센터·즉시 해결 약속으로 보이지 않게 함 |
| 이용 중지 | 現在このクエストは利用できません | 신규 시작과 기존 기록 읽기의 차이를 설명 |
| 나의 기록 | 自分の記録 | 계정 전체 이력이나 다른 기기 동기화로 오해되지 않게 함 |

일반 문장에서는 `一人`, 마케팅성 제목에서만 검수 후 `ひとり`를 허용한다. 두 표기를 의미 없이 섞지 않는다. `保存`, `記録`, `完了`가 실제 증명·영구 보존을 암시하는지도 문맥에서 확인한다.

## 문자열 단위 검수 질문

각 문구에 다음을 답한다.

1. 이 문구가 나타나는 서버·화면 상태는 무엇인가?
2. 사용자가 다음에 할 수 있는 행동과 할 수 없는 행동은 무엇인가?
3. 번역만 보고도 손실·비용·보존·demo 한계를 이해하는가?
4. 주어·대상이 생략돼 다른 기록이나 기기를 뜻할 수 있는가?
5. 경어와 어조가 같은 흐름의 앞뒤 문구와 맞는가?
6. 날짜·금액·지역·단계 수 변수가 들어가도 문법이 유지되는가?
7. 360px 화면에서 의미 있는 단어가 잘리지 않는가?
8. screen reader가 읽을 때 icon이나 색 없이 상태를 이해하는가?

좋아하는 표현을 고르는 투표보다 실제 화면에서 “무슨 일이 일어나며 다음에 무엇을 할 수 있는가”를 설명하게 한다.

## 변수와 형식

- placeholder 이름과 중괄호는 검수 중 번역하지 않는다.
- API의 UTC ISO 값과 화면의 일본어 날짜 표시를 구분한다.
- 숫자와 단위 사이 표기, 원화 범위, 분 단위를 화면 전체에서 통일한다.
- 0원과 가격 미확인을 구분한다.
- 복수형이 없는 일본어라도 단계 수·건수의 값이 바뀌는 예시를 본다.
- 오류 code와 route 이름은 사용자 문구에 노출하지 않는다.

검수용 예시는 최소값·최대값·긴 지역명·긴 quest 제목·null 가격을 포함한다.

## 한국어 요청 카드 검수

각 pair에 다음을 기록한다.

| 항목 | 기록 |
| --- | --- |
| 사용 상황 | 누구에게 언제 보여 주는지 |
| 한국어 원문 | 실제 카드 문구 |
| 일본어 뜻 | 같은 요청을 자연스럽게 설명 |
| 존댓말 수준 | 현장 관계에 적절한지 |
| 예상 응답 | 사용자가 이해해야 할 핵심 응답 |
| 오해 위험 | 수량·가격·알레르기·예약 등 |
| 검수 코드·날짜 | KR·JR 각각 |

한국어를 단어별 직역하지 않는다. 일본어 뜻이 더 넓거나 좁은 요청이 되면 공개하지 않는다. 음성·발음 표기는 P0에 없으며 로마자만으로 정확성을 보장한다고 표현하지 않는다.

## 4단계 상태

| 상태 | 의미 | 공개 가능 여부 |
| --- | --- | --- |
| `draft` | 작성자 초안 | 불가 |
| `linguistic_reviewed` | 모어 화자가 문장 단위 확인 | 조사 문안은 조건부, 제품 공개는 아직 불가 |
| `in_context_verified` | 실제 화면·폭·상태 전이에서 확인 | 관련 사실·권리 검수도 통과하면 가능 |
| `blocked` | 의미·사실·제품 동작이 불명확 | 불가 |

문서에서 자연스럽다는 이유만으로 `in_context_verified`로 올리지 않는다. 상태가 바뀌면 검수 범위와 근거 commit을 기록한다.

## 검수 실행 순서

1. 작성자가 문구 inventory와 상태·행동 설명을 준비한다.
2. 검수자는 제품 설명 없이 문구 또는 화면만 보고 의미와 다음 행동을 말한다.
3. 작성자가 의도와 다른 부분을 기록하되 먼저 정답을 설명하지 않는다.
4. 검수자가 자연스러운 수정안을 제안하고 의미 차이를 설명한다.
5. 작성자가 API·화면 상태·콘텐츠 사실과 다시 대조한다.
6. 수정본을 360px과 실제 일본어 locale에서 확인한다.
7. 한국어 카드면 별도 pair 검수를 완료한다.
8. 결과를 기능 단위로 커밋하고 영향받는 테스트 fixture를 갱신한다.

검수 중 나온 새 기능 요구는 문구 수정에 섞지 않는다. 사용자 행동이나 데이터 의미가 달라지면 제품 결정으로 별도 기록한다.

| --- | --- | --- | --- | --- | --- |
|  |  |  | draft / linguistic_reviewed / in_context_verified / blocked |  | 없음 / 있음 |

- 관찰:

## 보류 항목

- 문구:
- 불명확한 사실 또는 동작:

긴 문구 원문을 audit log나 issue 제목에 반복하지 않는다. 검수 기록에는 공개 가능한 제품 문구만 넣고 참여자 발언·연락처는 넣지 않는다.

## 변경 영향

다음 변경은 단순 copy commit으로 처리할 수 있다.

- 의미와 행동이 같은 자연스러움·띄어쓰기·표기 통일
- 레이아웃을 깨지 않는 길이 조정
- 같은 사실 범위 안의 경어 조정

다음은 계약 변경이다.

- 시작이 session 생성·run 생성 중 무엇인지 달라짐
- 완료가 실제 방문 인증처럼 해석되거나 그 반대
- 중지·삭제·보존·복구 가능 범위가 달라짐
- 오류 뒤 재시도·목록 이동 등 허용 행동이 달라짐
- 비용·혼자 이용·검수일의 사실 범위가 달라짐

계약 변경이면 [B2C 스펙](B2C_SPEC_v0.1.md), API 예시, 화면 상태, 테스트와 변경 기록을 같은 기능 단위에서 갱신한다.

## 공개 전 gate

- [ ] P0 문구가 모두 `in_context_verified`다.
- [ ] 검수자 코드·날짜·대상 commit이 있다.
- [ ] demo·완료·보존·삭제 의미를 설명 없이 이해했다.
- [ ] 한국어 요청 카드 pair가 두 언어에서 확인됐다.
- [ ] 긴 값·null·오류·중지 상태를 360px에서 확인했다.
- [ ] 일본어 locale의 날짜·금액·screen reader 언어를 확인했다.
- [ ] blocked 문구가 공개 bundle·콘텐츠에 없다.
- [ ] 검수 뒤 제품 의미 변경이 계약과 테스트에 반영됐다.

검수 인원이 한 명이거나 화면 검수가 끝나지 않았다면 그 한계를 표시하고 제품 공개 완료로 간주하지 않는다.
