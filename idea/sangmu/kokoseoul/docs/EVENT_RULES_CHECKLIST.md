# 해커톤 사전 개발 범위 확인서

작성일: 2026-11-21 · 상태: 주최 측 확인 필요

사전 코드 게이트: `CLOSED`
게이트 근거: 미기록
허용 시작 시각: 미기록

`CLOSED`는 문서·조사·Python 검증 도구만 허용하고 scaffold·workflow·제품 파일을 금지한다. 공식 답변이 빈 개발 환경만 허용하면 답변 기록과 gate commit에서 `F0_ONLY`로, 제품 코드까지 허용하면 `PRODUCT_ALLOWED`로 바꾼다. 열린 gate는 공개 가능한 근거 요약과 timezone offset을 포함한 ISO 8601 시작 시각도 함께 기록해야 한다. `F0_ONLY`에서도 API·DB·domain module·migration은 금지되며 중립 scaffold 여부는 수동 검수한다. 답변 근거 없이 이 값을 바꾸지 않는다.

공유된 행사 안내에서는 행사 전 아이디어 도출, 기술 조사, 개발 환경 준비가 허용된다고 이해했다. 제품 코드, DB 마이그레이션, 실제 배포와 콘텐츠 제작이 행사 전에 허용되는지는 근거가 없다. 공식 답변을 받기 전에는 설계·조사·계약·환경 점검만 진행하고 제품 코드는 작성하지 않는다.

## 현재 확인된 범위

| 항목 | 현재 판단 | 근거 상태 |
| --- | --- | --- |
| 아이디어 도출 | 허용 | 제공된 안내 이미지 요약 |
| 기술 조사 | 허용 | 제공된 안내 이미지 요약 |
| 개발 환경 준비 | 허용 | 제공된 안내 이미지 요약 |
| 저장소와 문서 작성 | 준비 작업으로 진행 중 | 명시적 금지 근거 없음, 최종 확인 필요 |
| 제품 화면·API 코드 | 보류 | 허용 근거 없음 |
| DB schema·migration 실행 | 보류 | 허용 근거 없음 |
| preview·production 배포 | 보류 | 허용 근거 없음 |
| 실제 콘텐츠 공개 | 보류 | 행사 규칙 외 권리·사실 검수도 필요 |

안내 이미지 요약은 공식 원문을 대체하지 않는다. 답변은 원문 링크, 공지 캡처 또는 주최 측 담당자의 메시지와 함께 기록한다.

## 주최 측에 보낼 질문

아래 문안을 그대로 보내되, 행사명·팀명·문의 채널만 채운다.

> 안녕하세요. 행사 전 준비 가능 범위를 정확히 확인하고 싶어 문의드립니다.
>
> 안내에서 아이디어 도출, 기술 조사, 개발 환경 준비가 가능하다고 확인했습니다. 다음 항목을 행사 전에 진행해도 되는지 각각 알려주실 수 있을까요?
>
> 1. Git 저장소 생성과 README·기획·API·데이터 설계 문서 작성
> 2. Next.js 프로젝트 생성, lint·test·CI 같은 빈 개발 환경 구성
> 3. 화면 컴포넌트, API, DB schema·migration 등 제품 코드 작성
> 4. 가상 데이터로 로컬 또는 preview 환경에 실행·배포
> 5. 사용자 인터뷰, 현장 조사, 퀘스트 콘텐츠 초안과 번역 작성
> 6. 행사 전 작성한 코드·문서·콘텐츠를 행사 결과물에 포함
> 7. 오픈소스 템플릿, UI 라이브러리, AI 코딩 도구 사용과 출처 표기 기준
>
> 허용되는 시점, 공개 저장소 여부, 기존 작업 공개 또는 제출 시 필요한 증빙도 함께 안내 부탁드립니다.

짧은 메신저 문의가 필요하면 다음을 사용한다.

> 행사 전 준비 범위를 확인하고 싶습니다. 기획·API 문서 외에 빈 Next.js 환경, 제품 코드, DB schema, preview 배포, 사용자 인터뷰·콘텐츠 초안까지 각각 사전 진행이 가능한가요? 기존 작업 공개·출처 표기 기준도 부탁드립니다.

## 반드시 확인할 세부 항목

| 질문 | 확인 이유 |
| --- | --- |
| 제품 코드 작성 가능 시작 시각 | 커밋 시각과 행사 공정성 판단 기준 |
| 빈 scaffold·CI가 개발 환경 준비에 포함되는지 | F0 착수 가능 여부 |
| schema·migration이 문서인지 제품 코드인지 | F1 착수 가능 여부 |
| 인터뷰·현장 검증·콘텐츠 초안 허용 여부 | 첫 지역과 퀘스트 선정 가능 여부 |
| preview 배포 허용 여부 | 외부 서비스 설정과 모바일 검수 가능 여부 |
| 기존 오픈소스·템플릿 허용 범위 | 재사용 코드와 출처 기록 방식 |
| AI 도구 사용·표시 기준 | 생성 코드·문서 제출 규칙 |
| 사전 커밋 공개 또는 제출 방식 | 개인 저장소 이력을 팀 결과물로 옮기는 방법 |
| 팀 저장소 이전과 commit history 인정 여부 | 개인 준비 작업의 팀 기여 증빙 |
| 심사 제출 마감과 운영 URL 조건 | 배포·검수 일정 산정 |

## 답변에 따른 작업 경계

### 문서와 환경 준비만 허용

- 사용자 조사와 퀘스트 후보 검증
- API·데이터·화면 상태 계약
- 의존성·호스팅·인증·지도 기술 조사
- 로컬 도구 설치 여부와 버전 확인
- 제품 파일을 생성하지 않는 실행 계획

Next.js scaffold, DB schema, 화면, API, 테스트 코드는 행사 시작까지 보류한다.

### 빈 개발 환경까지 허용

- 구현 계획 F0만 진행
- 기본 Next.js 화면은 제품 디자인·문구·도메인 동작을 포함하지 않음
- lint, typecheck, test runner, CI, `.env.example` 구성
- F1 이후 제품 schema와 기능은 보류

### 제품 코드까지 허용

- 허용 시작 시각 이후 F0부터 구현 계획 순서대로 진행
- 사전 커밋과 행사 중 커밋을 이력에서 구분
- 제공된 템플릿·AI·오픈소스 출처 조건을 저장소에 반영
- preview 배포는 별도 허용 여부를 확인

### 답변이 불명확하거나 상충

- 더 넓은 권한으로 해석하지 않는다.
- 구체적인 파일·작업 예를 들어 다시 질문한다.
- 공식 공지와 개인 답변이 다르면 주최 측에 우선순위를 확인한다.

## 게이트 해제 절차

1. 답변 원문과 날짜를 확인한다.
2. 항목별 허용·금지·조건을 이 문서에 기록한다.
3. [구현 계획](IMPLEMENTATION_PLAN_v0.1.md)의 착수 게이트 상태를 갱신한다.
4. 허용된 첫 작업 단위와 시작 시각을 결정한다.
5. 규칙 확인 변경을 먼저 커밋·푸시한다.
6. 다음 커밋부터 허용된 구현을 시작한다.

주최 측 답변 없이 추정으로 제품 코드 게이트를 해제하지 않는다.

오픈소스·template·AI 도구 사용이 허용돼도 출처·license·검토 기록은 [의존성·에셋·AI 출처 관리](DEPENDENCY_ATTRIBUTION_v0.1.md)에 남긴다.
