# 2분 제품 시연 런북 v0.1

작성일: 2026-11-21 · 상태: 구현 전 리허설 기준

이 런북은 여기서울의 핵심 가설을 1~2분 안에 보여 주되, 데모 화면 완료를 실제 장소 방문이나 사용자 성과로 과장하지 않기 위한 진행 기준이다. 화면 계약은 [B2C 화면 상태](SCREEN_STATES_v0.1.md), 기술 장애 대응은 [배포와 복구 런북](OPERATIONS_RUNBOOK_v0.1.md)을 따른다.

## 한 문장 메시지

재방문 일본인 혼행객이 익숙한 관광지 밖의 새 장소를 포기하지 않도록, 선택 이유부터 현장에서 할 다음 행동과 한국어 요청 문장까지 일본어로 이어 준다.

이 문장은 아직 검증할 제품 가설이다. 인터뷰와 실제 사용 관찰 전에는 “일본인 여행객이 이 문제를 겪는다”거나 “방문을 늘렸다”고 단정하지 않는다.

## 시연 성공 조건

시연이 끝났을 때 관객이 다음 세 가지를 구분할 수 있어야 한다.

1. 검색 결과를 나열하는 서비스가 아니라 조건에 맞는 행동 단위를 안내한다.
2. 일본어 행동 안내와 한국어 요청 카드가 현장 불확실성을 줄인다.
3. 화면의 완료는 자기 확인 기록이며 실제 방문 인증이 아니다.

예약·결제·AI 자동 추천·업체 대시보드는 첫 시연에 포함하지 않는다. 질문을 받으면 후속 가능성으로만 설명하고 구현됐다고 말하지 않는다.

## 데모 데이터

시연용 quest는 다음 조건을 만족한다.

- `isDemo=true`, environment는 `demo`
- 제목·카드·상세·진행·완료에 `デモ体験` 표시
- 실제 이동이나 영업 중인 업체를 전제로 하지 않는 가상 체험
- 개인 이름·실제 연락처·허가받지 않은 사진 없음
- 3단계, 한국어 주소 1개, 한국어 요청 카드 1개
- 정보 확인일과 가상 데이터 설명 포함
- demo run·feedback은 production 지표에서 제외

실제 장소를 예시로 쓸 경우에도 운영시간·가격·혼자 이용 가능 여부를 검수하고, 해당 업체와 제휴하거나 방문을 보장한다는 표현을 쓰지 않는다. 권리와 사실 근거는 [콘텐츠 검수 계약](CONTENT_VERIFICATION_v0.1.md)에 기록한다.

## 100초 기본 시나리오

| 누적 | 화면과 행동 | 발표 문장 |
| --- | --- | --- |
| 0~10초 | 시작 화면에서 지역·관심사·시간을 선택 | “서울을 다시 찾은 일본인 혼행객이 새 장소를 고르려 하지만, 갈 수 있다는 정보만으로는 다음 행동을 결정하기 어렵다는 가설에서 시작했습니다.” |
| 10~25초 | 목록에서 추천 이유가 있는 demo 카드 선택 | “지역, 관심사, 가능한 시간을 그대로 반영하고 왜 이 선택지가 맞는지 일본어로 보여 줍니다.” |
| 25~40초 | 상세의 혼자 이용 조건·정보 확인일·단계 개요 확인 | “가기 전에 혼자 이용 가능한지와 정보가 언제 확인됐는지, 현장에서 무엇을 할지 먼저 확인합니다.” |
| 40~52초 | 시작 버튼, 30일 기록 안내, 기록 생성 | “명시적으로 시작할 때만 이 브라우저에 익명 진행 기록을 만들고 다른 기기와 공유하지 않습니다.” |
| 52~72초 | 1단계 주소 복사, 지도 fallback 언급 | “위치 권한 없이도 한국어 주소를 복사할 수 있어 지도 앱이 열리지 않아도 진행할 수 있습니다.” |
| 72~86초 | 한국어 요청 카드와 일본어 뜻 표시, 단계 완료 | “현장에서 바로 보여 줄 한국어와 그 뜻을 함께 제공해 다음 행동을 구체화합니다.” |
| 86~100초 | 마지막 단계 완료와 완료 카드 | “이 완료는 실제 방문 인증이 아니라 사용자가 단계를 확인한 기록입니다. 실제 가치 판단은 별도 사용자 관찰과 인터뷰로 검증합니다.” |

발표자는 화면을 읽지 않고 ‘선택 이유 → 행동 안내 → 요청 카드 → 정직한 완료 의미’만 설명한다. 네트워크가 정상이어도 100초를 넘기지 않도록 각 화면에서 보여 줄 항목을 하나로 제한한다.

## 60초 축약 시나리오

시간이 줄면 미리 열린 상세 화면에서 시작한다.

1. 0~15초: 추천 이유·혼자 이용 조건·단계 개요
2. 15~40초: 진행 화면의 주소와 한국어 요청 카드
3. 40~55초: 단계 자기 확인과 완료 카드
4. 55~60초: “demo이며 실제 방문 인증이 아니다”라고 명시

축약 시에도 demo 표시와 완료 의미는 생략하지 않는다. 필터 조작과 피드백 입력은 먼저 뺀다.

## 실패 시 대체 동선

| 실패 | 즉시 행동 | 말할 내용 |
| --- | --- | --- |
| 목록 API 지연 | 미리 연 상세 URL로 이동 | “목록보다 이후 행동 안내가 핵심이라 준비한 상세에서 이어가겠습니다.” |
| run 시작 응답 유실 | 새 run을 만들지 말고 기록 목록 또는 run URL 조회 | “응답이 끊겨도 서버 상태를 확인해 중복 진행을 만들지 않습니다.” |
| 단계 완료 응답 유실 | 같은 run 재조회, 완료됐으면 다음 단계 | “완료를 추측하지 않고 저장된 상태를 다시 확인합니다.” |
| 지도 앱 실패 | 한국어 주소 복사와 선택 가능한 주소 표시 | “지도 연결 없이도 주소로 진행할 수 있습니다.” |
| preview 전체 장애 | 로컬 고정 demo 또는 사전 녹화로 전환 | “현재는 녹화된 동일 흐름이며 실시간 서비스처럼 표현하지 않겠습니다.” |
| 발표 시간 60초 이하 | 축약 시나리오로 전환 | 가치 흐름과 demo 한계만 설명 |

장애를 숨기기 위해 production 기록을 직접 수정하거나 다른 사람의 run을 사용하지 않는다. 사전 녹화는 촬영 commit과 환경을 기록하고, 재생 시 녹화임을 알린다.

## 발표 직전 15분 확인

- [ ] 발표 commit과 배포 URL이 일치한다.
- [ ] 브라우저 확대 100%, 알림과 개인 탭을 닫았다.
- [ ] 새 시크릿 창에서 demo 배지와 일본어 문구가 보인다.
- [ ] 360px 또는 실제 모바일 폭에서 가로 스크롤이 없다.
- [ ] demo quest 시작·세 단계·완료가 한 번 통과한다.
- [ ] 주소 복사 실패 fallback을 확인한다.
- [ ] 유효한 run URL과 상세 URL을 별도 메모에 준비한다.
- [ ] preview와 production DB 연결이 분리돼 있다.
- [ ] 화면에 secret·관리자 계정·개인정보가 없다.
- [ ] 100초 타이머로 한 번 리허설한다.
- [ ] demo 기록이 production 지표에 합쳐지지 않는다.

## 발표 후 증적

시연 뒤 다음 정보만 저장소 또는 팀 기록에 남긴다.

```markdown
# 시연 기록 YYYY-MM-DD HH:mm KST

- commit:
- 환경: preview / local / recording
- 경로: 100초 / 60초 / fallback
- 실제 소요 시간:
- 성공한 핵심 흐름:
- 발생한 오류와 request ID:
- 관객 질문:
- 가설을 지지한 관찰:
- 반대하거나 불명확한 관찰:
- 후속 결정:
```

박수, 심사 의견, demo 완료 수를 실제 사용자 문제 검증으로 취급하지 않는다. 사용자 근거로 반영하려면 대상·상황·최근 실제 사례가 있는 별도 인터뷰 또는 사용 관찰로 기록한다.

## 질문에 대한 경계 답변

| 질문 | 답변 기준 |
| --- | --- |
| 실제 이용자가 있나 | 인터뷰·테스트 인원과 production 사용자를 분리해 정확한 수만 답함 |
| 방문을 늘렸나 | 방문 인증을 하지 않았으므로 입증하지 않았다고 답함 |
| 업체와 제휴했나 | 서면 확인된 제휴만 밝히고 내부 demo 공급자를 제휴로 표현하지 않음 |
| AI 추천인가 | 현재 정렬 규칙을 설명하고 사용하지 않은 AI를 주장하지 않음 |
| 결제 가능한가 | 첫 범위 밖이며 구현되지 않았다고 답함 |
| 개인정보는 무엇을 모으나 | 익명 브라우저 기록과 보존·삭제 범위를 설명하고 수집하지 않는 항목을 구분함 |
