# 역에서 시작하는 퀘스트 개발 계획 v0.1

작성일: 2026-11-23 · 상태: 퀘스트 담당 작업 계획

## 배경

주제가 지하철 가이드로 확정됐고 기능을 안내·퀘스트·스탬프 셋으로 나눠 맡는다. 퀘스트는 "지하철에서 내린 다음 무엇을 할지"를 맡는다. 안내가 역까지, 스탬프가 역 자체를 다룬다면 퀘스트는 역 출구에서 시작해 목적지에서 끝나는 30~120분의 행동이다.

남은 빈틈은 다음과 같다.

- **퀘스트가 지하철 화면과 이어지지 않는다.** 지하철 안내와 역 스탬프 도감에서 퀘스트로 가는 링크가 없고, 퀘스트 상세에도 어느 역 몇 번 출구로 나가야 하는지가 없다. 출구 정보는 Preview DB 등록 스크립트에만 있다.
- **출구 검색이 DB에만 의존한다.** 로컬이나 DB 장애 시 출구 목록이 비고, 24개 출구를 한 줄 드롭다운으로 고르는 방식이라 역을 먼저 떠올리는 사용자 흐름과 맞지 않는다.
- **퀘스트 등록 경로가 네 갈래다.** 개별 JSON 17개와 전용 route 폴더, 방문 가이드 목록 JSON 6개, 데모 퀘스트 TS, 해커톤 안내가 따로 있고 [상세 경로 함수](../src/modules/content/quest-detail-path.ts)가 이를 손으로 잇는다. 퀘스트 하나를 추가하려면 서너 곳을 고쳐야 한다.
- **노선 분포가 치우쳐 있다.** 29개 중 경복궁·명동·이촌·성수·안국·광화문 여섯 역에 17개가 몰려 있고 6·7·8호선 역은 하나도 없다. 일본인 방문객이 많이 내리는 홍대입구·을지로·이태원·고속터미널도 없다.

## 기술 개발

순서는 다른 담당 화면을 적게 건드리는 것부터다.

1. **출구 정보를 앱 콘텐츠로 쓴다.** 출구·시작점 목록을 앱이 직접 읽어 퀘스트마다 `가까운 역 출구`, 노선, 출구에서 시작점까지 직선거리를 계산하는 모듈을 둔다. DB 등록 스크립트와 앱이 같은 파일을 쓰므로 값이 갈라지지 않는다. 테스트로 모든 출구가 실제 역 이름과 맞고 모든 퀘스트가 상세 경로를 가지는지 확인한다.
2. **퀘스트 상세에 "몇 번 출구로 나가요" 카드를 붙인다.** 역 이름, 노선 색, 출구 번호, 직선거리를 보여 주고 지하철 안내(그 역)와 역 스탬프 도감(그 역)으로 가는 링크를 둔다. 걸리는 시간은 실제 도보 경로를 확인하기 전까지 쓰지 않는다.
3. **역으로 퀘스트를 찾는다.** `/quests/nearby?station=<역 코드>`로 그 역 출구에서 시작하는 퀘스트와 역 좌표 기준 반경 안의 퀘스트를 DB 없이 보여 준다. 출구 검색은 DB가 있을 때 그대로 쓰고, DB를 못 읽으면 역 기준 결과로 대신한다. 현재 위치 버튼은 지하철 안내의 가까운 역 찾기 로직을 재사용한다.
4. **다른 담당 화면에는 링크 하나만 요청한다.** 지하철 안내의 역 안내도와 스탬프 도감의 역 카드에 `이 역에서 시작하는 퀘스트 N개` 링크를 붙일 수 있도록 역 코드 → 퀘스트 수 함수를 제공한다. 링크 위치와 문구는 각 담당이 정한다.
5. **퀘스트 완료 후 다음 행동을 잇는다.** 완료 화면에서 그 역 스탬프 받기(스탬프 담당의 위치 확인 흐름 그대로)와 같은 역·같은 노선의 다음 퀘스트를 보여 준다. 스탬프를 퀘스트 완료만으로 자동 지급하지는 않는다.
6. **퀘스트 등록을 한 곳으로 모은다.** 슬러그·종류·상세 화면을 가진 퀘스트 목록 하나를 두고 상세 경로 함수와 전용 route 폴더를 이 목록에서 만든다. 다른 작업과 충돌이 크므로 1~5가 안정된 뒤 코덱스와 순서를 맞춘다.

## 콘텐츠 개발

1. **출구에서 시작하는 문장으로 바꾼다.** 퀘스트 요약 첫 문장을 "○○역 ○번 출구에서 ○분"처럼 역 기준으로 쓴다. 출구 번호는 출구 목록과 같은 값을 쓰고, 출구 밖 첫 장면(보이는 건물·간판)은 현장 확인 전까지 쓰지 않는다.
2. **역 이름 유래 퀘스트를 만든다.** 스탬프 도감의 역 이름 이야기 카드에서 이름의 주인공이 출구 가까이에 실제로 있는 역을 고른다(예: 동묘앞의 동묘, 독립문의 독립문, 낙성대의 낙성대 공원, 선정릉의 선릉·정릉, 효창공원앞의 효창공원). 도감에서 읽은 이야기를 현장에서 확인하는 퀘스트라 스탬프와 자연스럽게 이어진다.
3. **역 안에서 끝나는 퀘스트를 만든다.** 교통카드 충전, 1회용 교통카드 보증금 환급, 물품보관함, 역사 안 지하상가처럼 개찰구 근처에서 끝나는 짧은 퀘스트다. 지하철 안내가 다루는 이동 판단과 겹치지 않도록 "역에서 할 수 있는 일"에 한정한다.
4. **비어 있는 노선과 역을 채운다.** 6호선(이태원·합정·망원), 7호선(건대입구·고속터미널), 2호선(홍대입구·을지로입구), 9호선(고속터미널·노량진)을 먼저 본다. 공식 출처, 혼자 이용 가능 여부, 일본어 대응을 확인한 뒤 초안을 [퀘스트 초안](../research/desk/quest-drafts/README.md)에 쌓는다.
5. **노선 코스로 묶는다.** 같은 노선에서 환승 없이 이어지는 퀘스트 2~3개를 반나절 코스로 묶는다. 코스는 새 데이터가 아니라 기존 퀘스트의 순서 목록으로 둔다.

**공개된 퀘스트의 문구 수정.** 시드 스크립트는 이미 있는 퀘스트를 건너뛰어 JSON 수정이 진행 화면에 닿지 않았다. [상태 머신 계약](STATE_MACHINES_v0.1.md)의 "published → publish 새 version"을 따르는 `pnpm db:publish:content`를 더했다. 콘텐츠 파일의 `versionId`가 DB의 공개 버전과 다르면 새 버전을 공개하고, 기존 버전과 진행 기록은 그대로 둔다. 이번에 고친 퀘스트 4개(서울풍물시장, 낙산, 남산, 윤동주 시인의 언덕)는 새 `versionId`를 받았고 Preview DB에는 아직 공개하지 않았다. 관리자 API로 공개하는 경로가 생기면 그쪽에서 audit log를 남긴다(감사 로그는 활성 관리자만 받는다).

### 다른 담당 화면에 붙일 수 있는 링크

- 퀘스트 수: 서버 컴포넌트에서 `countStationQuests(code)`를 부르고, 0보다 크면 `/quests/nearby?station=<역 코드>#station-quests`로 링크한다. 클라이언트 컴포넌트에는 서버에서 계산한 숫자만 prop으로 넘긴다. 함수가 퀘스트 본문 JSON을 함께 불러오기 때문이다.
- 역 안내도: `/subway?station=<역 코드>#station-interior-title`
- 역 스탬프: `/station-album?line=<노선>&station=<역 이름>#station-story`

## 확인이 필요한 것

- 안내 담당: `/subway?station=<역 코드>`로 역 안내도를 바로 여는 변경을 유지해도 되는지, 경로 안내 결과의 도착역에 퀘스트 수 링크를 붙일지.
- 스탬프 담당: 도감의 역 카드에 퀘스트 링크를 둘 자리와, 퀘스트 완료 화면에서 스탬프 받기로 보내는 링크 형식(`/station-album?line=<노선>&station=<역 이름>`)을 그대로 써도 되는지.
- 역 이름 일본어 표기: 2·3호선 한자, 나머지 가타카나로 갈라져 있다([일본어 검수 시트](../research/desk/japanese-review/README.md)). 출구 목록은 한자(明洞駅)를 쓰므로 정해진 방침에 맞춰 함께 고친다.
