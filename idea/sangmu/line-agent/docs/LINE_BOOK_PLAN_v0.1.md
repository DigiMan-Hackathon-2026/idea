# 노선 도감 기획 v0.1

작성일: 2026-11-23 · 상태: 기획 초안, 콘텐츠 데이터 구현 · 기준 커밋: `8c481c2`

로스트아크 모험의 서처럼 **한 지역을 얼마나 경험했는지 퍼센트와 칸 채우기로 보여 주는 수집 화면**을 여기서울에 만든다. 로스트아크는 대륙별로 나누지만 여기서울은 **지하철 호선별**로 나눈다. 각 호선의 대표 역 주변에서 할 수 있는 맛집, 공연장, 문화생활, 관광지 경험으로 칸을 채운다.

가져오는 것은 **구조와 진행 방식**이다. 화면을 영역으로 나누는 방식, 칸마다 완료 표시를 하는 방식, 달성률 구간 보상을 따른다. 로스트아크의 이름(「모험의 서」 등), 아이콘, 일러스트, 색, 화면 장식은 쓰지 않는다. 겉모습은 기존 역 도감(스탬프)과 [서울색 UI 체계](SEOUL_COLOR_SYSTEM_v0.1.md)를 따른다. 기능 이름은 가칭 **노선 도감**(일본어 `路線図鑑`)이다. 기존 `역 도감`과 짝을 이룬다.

관련 문서: [역에서 시작하는 퀘스트 계획](QUEST_STATION_PLAN_v0.1.md) · [제품 요구사항](PRD_v0.1.md) · [콘텐츠 확인 기준](CONTENT_VERIFICATION_v0.1.md) · [접근성 기준](ACCESSIBILITY_VERIFICATION_v0.1.md)

## 1. 로스트아크 모험의 서 구조

게임 화면 두 장(아르테미스 86.6%, 루테란 동부 97.9%)과 공개 공략을 바탕으로 정리했다. 항목 이름은 한국어 게임 화면에 나오는 그대로 적었다.

### 화면 배치

| 영역 | 내용 |
| --- | --- |
| 왼쪽 위 | `대륙 선택`, 대륙 이름과 한두 줄 소개, 큰 달성률(예: 86.6%) |
| 왼쪽 가운데 | 보상 아이콘 10칸. 받은 보상에는 체크가 붙고, 아직 못 받은 구간에는 90%·100% 같은 기준값이 보인다. 그 아래 `보상 모두 받기` 버튼 |
| 왼쪽 아래 | `메인 퀘스트`: 그 대륙 이야기의 대표 그림 |
| 가운데 | `수집품` 7칸, `요리` 7칸, `뷰포인트` 5~10칸(풍경 썸네일), `던전`(가로로 긴 배너, 일반·어려움 두 표시) |
| 오른쪽 가운데 | `몬스터` 15칸(5×3), `보스`(세로로 긴 초상화) |
| 오른쪽 | `또 다른 이야기` 카드 2장, `숨겨진 이야기` 체크 목록 약 7개, `호감도`와 `스퀘어홀` 진행 막대 |

모든 칸은 **완료 = 컬러 그림 + 체크**, **미완료 = 어둡게 처리 또는 물음표**로 같은 규칙을 따른다. 빈 칸 하나만 봐도 무엇이 남았는지 알 수 있는 것이 핵심이다.

### 항목별 채우는 조건

| 항목 | 채우는 방법 |
| --- | --- |
| 메인 퀘스트 | 그 대륙의 마지막 메인 스토리 퀘스트 완료 |
| 수집품 | 지역에 숨겨진 특정 아이템 획득(탐색·상호작용·퀘스트 보상) |
| 요리 | 그 지역의 특별 요리를 먹기(상인 구매 또는 요리사에게 제작) |
| 뷰포인트 | 정해진 경치 좋은 지점까지 가서 감상 상호작용 |
| 던전 | 지역 던전을 일반·어려움 난이도로 각각 완료 |
| 몬스터 | 지역의 특정 몬스터 종류 처치 |
| 보스 | 필드 보스 처치 |
| 또 다른 이야기 | 지역 서브 스토리 퀘스트 묶음 완료 |
| 숨겨진 이야기 | 특정 행동으로 얻는 지역 이야기 기록 |
| 호감도 | 지역 NPC와의 관계를 최고 단계까지 올리기 |
| 스퀘어홀 | 지역 이동 지점 개방으로 추정. 영문 공략의 항목 목록과 화면 순서를 맞춰 본 추정이며, 확인되지 않았다 |

보상은 달성률 **10%마다 한 번씩** 받는 일회성 보상이다. 대륙 모험의 서를 다 채우면 완료 보상이 따로 있다.

| 몬스터 | **역 방문** | 15(5×3) | 그 역 근처에서 위치 확인 | 위치 확인 | 역 도감 스탬프 |
| 보스 | **노선 대표 명소** | 1 | 호선을 대표하는 큰 경험 하나(예: 고궁 정기 행사) | 위치 확인 + 시간 조건 | 정기 휴무 표시 |
| 또 다른 이야기 | **연작 퀘스트** | 2 | 같은 주제로 이어지는 퀘스트 2~3개 완료 | 각 퀘스트 완료 | 퀘스트 다음 단계 제안 |
| 숨겨진 이야기 | **숨은 이야기**(역 이름 유래·동네 기록) | 약 7 | 그 역 방문 또는 관련 퀘스트를 마치면 열림 | 다른 항목 완료로 자동 개방 | `getStationNameTeaser` |
| 호감도 | **단골도** | 막대 1 | 그 호선 장소에 다른 날 다시 방문 | 날짜가 다른 완료 기록 수 | 기록(`/my`) |
| 스퀘어홀 | **환승 마스터** | 막대 1 | 그 호선의 환승역에서 지하철 안내로 환승을 마침 | 지하철 안내의 환승 확인 | `/subway` 환승 안내 |

- **달성률**은 칸마다 가중치를 둔다. 가중치는 대표 코스 15, 대표 명소 10, 체험 각 5, 연작 각 5, 맛집·수집품·뷰포인트 각 2, 역 방문 각 1, 숨은 이야기 각 1, 단골도·환승 막대는 각 최대 5로 시작한다. 실제 칸 수가 정해지면 합이 100이 되게 다시 나눈다.
- **보상**은 10%마다 하나씩 받는다. 1차는 디지털 보상만 둔다.
  - 스탬프 테두리, 노선색 도장 변형, 일본어·한국어 칭호, 배경 그림
  - 100%: `○호선 마스터` 도장. 기존 스탬프처럼 PNG로 저장할 수 있다.
  - 실물 쿠폰·할인은 제휴처가 생긴 뒤 B2B 범위에서 따로 정한다.
- 칸이 아직 준비되지 않은 호선은 달성률 대신 `준비 중`을 보여 준다. 빈 칸으로 100%를 만들 수 있게 두지 않는다.

## 3. 완료를 확인하는 방법

| 방식 | 쓰는 곳 | 저장 위치 | 주의 |
| --- | --- | --- | --- |
| 퀘스트 완료 | 대표 코스, 맛집, 체험, 연작 | 서버의 진행 기록(지금 구조 그대로) | 완료 단계 문구가 실제 행동과 맞아야 한다 |
| 위치 확인 | 역 방문, 뷰포인트, 대표 명소, 수집품 가게 | 기기(localStorage). 좌표는 저장하지 않고 `확인됨/시각`만 남긴다 | 기존 스탬프 기준을 쓴다: 반경 200m, 브라우저 정확도 100m 이하 |
| 본인 확인 | 수집품 구입 | 기기 | 사진 업로드는 받지 않는다. 개인정보와 권리 문제가 커지기 때문이다 |
| 지하철 안내 연동 | 환승 마스터 | 기기 | 지하철 안내(안내 담당 영역)가 환승 완료를 알려 줘야 한다. 안내 담당과 이벤트 형식을 맞춘다 |
| 자동 개방 | 숨은 이야기 | 기기 | 연결된 항목이 완료되면 열린다 |

- 위치와 진행 기록의 개인정보 기준은 [보안과 개인정보](SECURITY_PRIVACY_v0.1.md), [방문자 세션](VISITOR_SESSION_LIFECYCLE_v0.1.md)을 따른다. 기기에 남는 기록은 `/my`의 전체 삭제로 함께 지운다.
- 부정 사용은 막기보다 **오해 없이 보여 주는 쪽**을 택한다. 위치 확인 칸과 본인 확인 칸을 표시로 구분한다. 랭킹·경쟁 요소는 넣지 않는다.
- 콘텐츠 규칙: 영업 중, 대기 없음처럼 실시간으로 단정하는 표시는 쓰지 않는다. 공식 출처와 확인일을 둔다. 정기 휴무는 지금 퀘스트처럼 요일 규칙과 오늘 요일만 알린다. [콘텐츠 확인 기준](CONTENT_VERIFICATION_v0.1.md)

## 4. 화면

### 모바일(우선)

```text
┌──────────────────────────────┐
│ [1][2][3][4][5][6][7][8][9]  │ ← 호선 칩(노선색 원형 번호, 가로 스크롤)
├──────────────────────────────┤
│ 4호선  ・・・ 저녁 풍경 배경     │
│ 명동·남산에서 대학로까지          │
│        ( 62.5% )             │ ← 큰 달성률, 도장 테두리 안
│ ◉◉◉◉◉◉○○○○  보상 모두 받기     │ ← 10칸 보상 트랙(가로 스크롤)
├──────────────────────────────┤
│ ▸ 노선 대표 코스   ✓            │ ← 섹션은 접고 펼치는 카드
│ ▸ 역 방문 9/15                │    펼치면 칸 격자(3열)
│ ▸ 맛집 한 그릇 3/7              │
│ ▸ 전망·사진 지점 4/6            │
│ ▸ 체험 1/3 (도전 0)            │
│ ▸ 로컬 수집품 2/7               │
│ ▸ 노선 대표 명소  ○             │
│ ▸ 연작 퀘스트 1/2               │
│ ▸ 숨은 이야기 4/7               │
│ 단골도 ▓▓▓░░  환승 마스터 ▓▓░░░   │
└──────────────────────────────┘
```

### 태블릿·데스크톱

로스트아크처럼 4열 배치를 쓴다.

1. 요약: 달성률, 보상, 대표 코스
2. 맛집·수집품·뷰포인트·체험
3. 역 방문·대표 명소
4. 연작·숨은 이야기·막대

### 디자인 규칙

- **칸 = 도장.** 완료한 칸은 기존 스탬프의 전통 문양 도장(단청·소나무·기와·구름·매듭·살창·꽃·물결)을 노선색 테두리로 찍는다. 미완료 칸은 돌담회색(`#a4a199`) 윤곽과 `?`로 둔다. 로스트아크의 노란 체크 표시는 쓰지 않는다.
- 노선색은 호선 칩, 도장 테두리, 진행 막대처럼 **호선을 구분하는 곳에만** 쓴다. 면·버튼·상태 색은 서울색 체계를 따른다. 완료는 남산초록, 주의·시간은 은행노랑이다.
- 배경은 기존 화면 규칙을 따라 아침(스탬프 계열) 풍경을 쓴다. 노선 대표 코스 그림은 여기서울 풍경 일러스트 톤으로 새로 그린다.
- 칸을 누르면 아래에서 시트가 올라온다. 시트에는 다음이 들어간다.
  - 장소 이름, 역과 출구, 완료 조건, 확인 방법(위치/본인/퀘스트)
  - `여기까지 가는 길 찾기`(지하철 안내로 연결), 관련 퀘스트로 가는 링크
- 접근성: 완료 여부를 색과 도장 모양만으로 알리지 않는다. 칸마다 `획득 완료/미획득` 글자와 `aria-label`을 단다. 격자는 목록 구조로 만들고, 칸은 44px 이상으로 한다. 일본어 화면 안의 한국어 장소명에는 `lang="ko"`를 붙인다(`KoreanAwareText`). [접근성 기준](ACCESSIBILITY_VERIFICATION_v0.1.md)

## 5. 호선별 콘텐츠 계획

`✓`는 이미 있는 퀘스트(출구 좌표 연결 기준)이다. 나머지는 **후보이며 검증 전**이다. 후보는 [퀘스트 초안 공개 절차](../research/desk/quest-drafts/PUBLISHING.md)를 거쳐야 칸이 된다. 맛집·가게는 공식 출처, 혼자 이용 가능 여부, 일본어 대응을 확인한 뒤 정한다. 여기서는 동네와 장소 유형까지만 적는다.

현재 호선별 퀘스트 수(환승역은 양쪽에 셈): 1호선 4, 2호선 7, 3호선 7, 4호선 9, 5호선 3, 6호선 0, 7호선 0, 8호선 0, 9호선 1. 서울숲 산책 퀘스트(수인분당선 서울숲역)는 1~9호선 밖이다.

- **순서:** 콘텐츠가 이미 있는 4·3·2호선으로 먼저 노선 도감을 연다. 1·5호선이 그다음이다. 6~9호선은 퀘스트가 5개 이상 모일 때까지 `준비 중`으로 둔다.
- **환승역** 퀘스트는 여러 호선 도감에 함께 들어간다. 한 번 완료하면 해당하는 모든 호선 칸이 채워진다.
- **공연장** 칸은 공연 자체를 보증하지 않는다. "공연장까지 가서 입장 줄과 매표소 위치를 확인하고 한국어로 표를 받는다"처럼 우리가 안내할 수 있는 행동으로 쓴다. 예매·결제는 범위 밖이다.

## 6. 데이터와 구현

실제 타입은 [`types.ts`](../src/modules/content/line-book/types.ts)에 있다. 칸 하나는 다음 필드를 가진다.

- `id`, `lines`(환승역 항목은 여러 호선), `category`, `stationCode`, `titleJa`/`titleKo`, `weight`
- `check`: 완료 조건. 다음 다섯 가지 중 하나다.
  - `quest`(퀘스트 완료)
  - `location`(좌표·반경)
  - `unlock`(다른 칸 완료 후 열림)
  - `transfer`(환승역 목록, 부분 점수)
  - `revisit`(다른 날 횟수, 부분 점수)

본인 확인(`self`)은 수집품 칸에 퀘스트가 아닌 항목이 생길 때 추가한다. 출처와 확인일은 칸이 아니라 참조하는 퀘스트·역 데이터에 있다.

- **콘텐츠:** 아래 "구현된 콘텐츠 데이터"를 따른다. 사람이 정하는 부분은 `curation.json` 하나에 두고, 나머지는 기존 데이터에서 만든다.
- **진행:** 퀘스트 완료는 서버 진행 기록에서 계산한다. 위치·본인·환승·숨은 이야기는 기기 저장소(`yeogiseoul.line-book.v1`)에 `{entryId, checkedAt}`만 남긴다. 오프라인 퀘스트 저장과 같은 방식으로 `useSyncExternalStore` 저장소를 만든다.
- **달성률 계산:** 순수 함수 `computeLineProgress(book, progress)`로 구현했다(단위 테스트 포함). `보상 모두 받기`로 받은 구간 기록은 화면 쪽에서 기기 저장소에 둔다.
- **화면:** `/line-book`(호선 칩), `/line-book/[line]`. 칸 상세 시트에서 `/subway?to=<역코드>`와 퀘스트 상세로 이어 준다.
- **다른 담당과의 경계:**
  - 역 방문과 스탬프는 같은 위치 확인을 쓴다. 스탬프 담당과 "스탬프를 받으면 역 방문 칸도 채운다"를 합의한다.
  - 환승 마스터는 지하철 안내에서 환승 완료 이벤트가 나와야 한다. 안내 담당과 이벤트 형식을 맞춘다.

### 구현된 콘텐츠 데이터 (2026-11-23)

화면보다 먼저 칸에 들어갈 데이터와 달성률 계산을 만들었다. 새 장소는 넣지 않았다. 이미 공개 기준을 통과한 퀘스트, 역 데이터, 역 이름 유래 카드, 노선 코스만 엮었다.

| 파일 | 역할 |
| --- | --- |
| `src/modules/content/line-book/curation.json` | 사람이 정하는 부분만 둔다: 열린 호선, 퀘스트별 항목, 노선 코스·대표 명소, 연작 묶음, 역 방문 15곳, 이야기 7곳, 가중치 |
| `src/modules/content/line-book/build.ts` | 위 파일과 기존 데이터로 칸 목록을 만든다. `getLineBook(line)`은 열리지 않은 호선이면 `null`을 돌려준다 |
| `src/modules/content/line-book/progress.ts` | `computeLineProgress(book, progress)`: 칸별 완료(0~1), 항목별 개수, 달성률(소수 한 자리), 받은 10% 보상 단계 |
| `src/modules/content/line-book/types.ts` | 칸과 완료 조건 타입 |

- **자동으로 정해지는 것:** 칸 제목은 퀘스트·코스 제목과 역 이름에서 가져온다. 역 방문 좌표는 `station-coordinates.json`에서, 반경은 스탬프와 같은 200m다. 숨은 이야기 제목은 역 카드의 일본어 제목에서 가져오고, 그 역 방문 칸을 채우면 열린다. 환승 마스터는 1~9호선 안에서 같은 이름의 역이 다른 호선에도 있으면 환승역으로 센다.
- **칸 id는 저장 기록이 참조한다.** 형식은 `quest:<slug>`, `station:<역코드>`, `story:<역코드>`, `course:<slug>`, `landmark:<slug>`, `series:<id>`, `regular:<호선>`, `transfer:<호선>`이다. 바꾸면 저장된 진행이 끊긴다.
- **환승역 퀘스트:** 퀘스트 칸 하나가 열린 호선 전부에 들어간다. 지금은 동대문(1·4호선)이 1호선이 닫혀 있어 4호선에만 나온다. 연작 `한양도성 성곽 두 구간`은 3·4호선에 함께 들어간다.
- **대표 명소로 고른 퀘스트**는 그 호선에서는 체험 칸이 아니라 대표 명소 칸으로만 나온다.

## 8. 열린 결정

- 이름: `노선 도감`(가칭)으로 할지, 다른 이름으로 할지
- 진행을 기기에만 둘지, 퀘스트처럼 서버에도 둘지. 기기를 바꾸면 위치 확인 칸이 사라진다.
- 보상 구성: 디지털 보상만으로 시작하는 데 동의하는지
- 체험의 `도전` 모드(한국어 카드만으로 완료)를 넣을지
- 6~9호선을 `준비 중`으로 보여 줄지, 아예 숨길지
- 단골도를 "다른 날 재방문"으로 셀지, "같은 동네 퀘스트 수"로 셀지
