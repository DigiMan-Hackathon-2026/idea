# LINE 여행 비서 구현 계획

작성일: 2026-11-25 · 상태: 데모 범위 구현 완료, 외부 계정 연결 대기 · 기준 스펙: [LINE 여행 비서 스펙](LINE_AGENT_SPEC.md) · 실행: [실행 안내](LINE_AGENT_RUNBOOK.md)

11/29 본선 3분 시연이 끝까지 돌아가는 것을 먼저 만들고, 스펙의 나머지는 그 위에 쌓는다. 외부 계정(LINE 채널, OpenAI, Twilio)이 없어도 개발과 시험이 되도록 모든 외부 연동은 어댑터 뒤에 두고, 로컬에서는 시뮬레이터로 대신한다.

## 데모 우선 범위

| 영역 | 이번에 만드는 것 | 뒤로 미루는 것 |
| --- | --- | --- |
| LINE 접점 | 웹훅 서명 검증, 이벤트 중복 제거, 1:1·그룹, 그룹 호출어, 요청자 권한, postback revision 검사, reply/push | 리치 메뉴, LIFF |
| 요청 해석 | 일본어·한국어 규칙 기반 해석(인원, 지역, 메뉴, 도착 마감, 다음 장소), 빠진 항목 하나씩 질문 | LLM 해석 어댑터는 키가 생기면 켬 |
| 후보 | 신촌 큐레이션 후보(최대 3곳), 출처·검수일 표시, 네이버 지역 검색 보충(키 필요) | 실매장 검수 |
| 대기·시간 | 텍스트·캡처 이미지 대기 정보(분·팀 수·원격 대기) 판독, 착석 마감·착석 예상·`fits/late/unknown` 계산 | — |
| 이동 | TMAP 도보(키 있음), 대중교통은 거리 기반 추정치로 표시 | ODsay |
| 전화 | 승인 카드(후보 최대 2곳·후보당 1회·10분 유효), 순차 발신, 통화 결과 판정, 범위 밖 제안·예약금·결과 불명확 처리 | 실매장 발신 |
| 전화망 | 시뮬레이터(로컬·시연 보험), KAT 클라우드(070) 또는 Twilio + GPT-Live 중계(키가 생기면) | SIP 직접 발신 |
| 이동 연결 | `/go` 화면: 식당까지·다음 장소까지, 여기서울 지하철 안내와 네이버지도 링크, 한국어 예약 카드 | 출구 단위 매핑 |
| 저장 | 저장소 인터페이스 + 메모리 구현(로컬·테스트), PostgreSQL 구현과 24시간 정리 | 스펙의 테이블별 분리 |

스펙과 다르게 가는 점: 요청 한 건을 `dining_requests` 한 행(jsonb 본문 + revision)으로 저장한다. 후보·대기·승인·시도는 그 안에 둔다. 발신 시도와 웹훅 이벤트만 별도 테이블로 두어 유니크 제약으로 중복을 막는다. 사흘 안에 끝내기 위한 선택이며, 운영 단계에서 스펙의 테이블로 나눈다.

## 진행 상황 (2026-11-25)

| 스펙 항목 | 상태 | 확인 방법 |
| --- | --- | --- |
| 1. LINE과 후보 검색 | 완료: 웹훅 서명·중복 제거, 1:1·그룹(호출어·멘션), 요청자 권한, 인원 분기(1명·5명+·정원 초과 제외), 신촌·성수 테스트 후보 | `agent.test.ts`, `line/line.test.ts` |
| 2. 웨이팅·일정 계산 | 완료: 텍스트·캡처 이미지(OCR) 대기(분·팀 수·원격 대기·입장 시각), 다른 가게 화면 거부, 착석 마감·예상, 기준 미확인 시 질문 | `plan.test.ts` (ETA-01, WAIT-01) |
| 3. 여기서울 이동 연결 | 완료: `/go`(지하철 안내·네이버 지도·역 도감 링크), `/go/card` 한국어 예약 카드 | e2e `line-agent-simulator.spec.ts` |
| 4. 팀원 폰 발신 | 코드 완료, 실통화 미검증: 승인 카드, 순차 발신, 결과 판정, 범위 밖·예약금·불명확·미연결 처리, 음성 중계 | `agent.test.ts` (CALL-01~03), `pnpm voice:selftest` |
| 5. 기존 체험 연결 | 완료: 원격 대기로 시간이 남을 때 역 주변 미션(모험의 서) 제안, 역 도감(스탬프) 링크 | `agent.test.ts` |
| 저장 | 완료: 메모리(기본), PostgreSQL(`LINE_AGENT_STORE=postgres`, 마이그레이션 0009, 24시간 정리) | `tests/integration/line-agent-store.test.ts` |

네이버 지역 검색 보충은 코드 완료(키를 넣으면 켜짐: 큐레이션 후보가 3곳 미만일 때 '검색 후보·확인 안 됨'으로 붙고, 전화하지 않음). 아직 하지 않은 것: LLM 해석 어댑터, 실매장 후보 검수. 리치 메뉴는 `pnpm line:richmenu`로 만든다.

## 사람이 준비할 것

| 항목 | 쓰는 곳 | 없을 때 |
| --- | --- | --- |
| LINE 공식 계정 채널 시크릿·채널 액세스 토큰, 그룹 참여 허용 | 실제 LINE 연결 | 로컬 시뮬레이터로만 시험 |
| 공개 HTTPS 주소(cloudflared 등) | LINE 웹훅, 전화 음성 중계 | 로컬 시뮬레이터 |
| OpenAI API 키(GPT-Live) | 한국어 음성 통화 | 전화 시뮬레이터 |
| KAT 클라우드 가입(API 키·070 번호) 또는 Twilio 유료 계정·번호·한국 발신 허용 | 실제 발신 | 전화 시뮬레이터 |
| 시험 전화를 받을 팀원 번호(동의) | 데모 매장 역할 | 시뮬레이터의 매장 대본 |
| 신촌 후보 식당 검수 (`src/modules/line-agent/candidates.json`) | 후보 카드 | 테스트 표시가 붙은 후보 |
| 네이버 검색 API 키 (`NAVER_SEARCH_CLIENT_ID/SECRET`) | 후보 보충 | 큐레이션 후보만 |
