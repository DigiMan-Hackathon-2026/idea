> **15人に配れる、予算内で、帰国後も日持ちする。**

## 1. 핵심 한 가지: 「配れる保証」(나눠 줄 수 있음 보장)

이 앱이 "그냥 추천 챗봇"과 다른 점은 딱 하나로 말할 수 있어야 한다.

**추천된 모든 선물은 아래 4개 조건을 코드가 검사해서 통과한 것만 나온다.**

| 보장 | 검사 방법 (코드) | 결과 카드 표시 |
|---|---|---|
| ✓ 人数 (인원) | `팩 수 × 팩당 개수 ≥ 인원`, 모자라면 팩 수를 올림 | 「15人分 ✓ (2個あまり)」 |
| ✓ 予算 (예산) | 그룹 소계 ≤ 그룹 예산, 전체 합계 ≤ 전체 예산 | 「¥3,200 / ¥3,500 ✓」 |
| ✓ 日持ち (보관) | 최소 유통기한 ≥ 귀국까지 일수 + 30일 | 「帰国後1か月以上 ✓」 |
| ✓ アレルギー | 선택한 알레르기 성분이 하나도 없음 | 「小麦・乳 不使用 ✓」 |

- LLM은 이 검사를 **통과한 후보 안에서만** 고르고, 일본어 추천 이유만 쓴다.
- LLM이 낸 상품 ID가 DB에 없거나 조건을 깨면 **버리고 규칙 기반 1순위로 대체**한다.
- 발표 한 문장: **"AI는 고르고 말하는 역할, 숫자와 안전은 코드가 책임진다."**

> 결과 화면 상단에 4개 체크 배지를 항상 띄운다. 이것이 심사위원이 기억할 "명확한 무언가"다.

### 2-1. 평가 기준별 현재 상태

| 평가 항목 (배점) | 현재 강점 | 부족한 점 | 해야 할 것 |

| **팀 개발 (10)** | 역할 분담이 자연스러움 | — | 역할표와 의사결정 기록을 발표 1장에 |

### 2-2. 냉정한 판단

- **이길 수 있는 지점:** 테마가 "기쁘게"인데 대부분의 팀은 관광 정보·번역·맛집 추천으로 갈 가능성이 높다. *"일본인이 돌아가서 동료에게 건네는 순간"*까지 다루는 팀은 드물고, 심사위원(일본인)이 **직접 겪어 본 고민**이라 공감 점수가 높다.
- **질 수 있는 지점:**
  1. "올리브영이나 면세점에서 사면 되지 않나?" → 문제의 크기가 작아 보일 위험. **고민의 핵심은 '어디서'가 아니라 '몇 개·얼마·개별 포장·라벨'** 이라는 걸 인터뷰 숫자로 보여 줘야 한다.
  2. 데모에서 LLM·지도가 멈추면 기술력 25점이 크게 깎인다. **대체 동작이 필수**다.
  3. 유용하지만 기쁘지는 않은 앱으로 보일 수 있다. 감동 장면을 설계해야 한다.
- **결론:** 컨셉은 테마에 잘 맞고 경쟁력이 있다. 단, **① 인터뷰 근거 ② 실제로 동작하는 지도·LLM ③ 데모 마지막의 감동 장면** 세 가지가 갖춰져야 상위권이다.

### 2-3. 「ChatGPT에 물어보면 되지 않나요?」 답변

| | ChatGPT | オミヤゲ・ソウル |
|---|---|---|

## 3. 기능 명세

상태: ✅ 시안 완료 (목업) · 🔧 실제 구현 필요 · ⏳ 여유 있을 때

### F-01. 받을 사람 그룹 입력 — 필수

| 항목 | 내용 |
|---|---|
| 입력 | 그룹명, 아이콘, 인원(1–99), 1인당 예산(₩500 단위), 격식(カジュアル/ふつう/きちんと) |
| 동작 | 그룹 추가(프리셋 6종: 上司·取引先·ご近所·サークル·親戚·先生), 삭제, ± 조절 |
| 출력 | 전체 인원, 전체 예산(₩, ≈¥) 실시간 합계 |
| 완료 기준 | 그룹 1개 이상 필수, 삭제 시 마지막 1개는 막음 |
| 상태 | ✅ |

### F-02. 조건 입력 — 필수

| 항목 | 내용 |
|---|---|
| 입력 | 보관(상온만/냉장 OK), 귀국일, 짐 무게(軽く/ふつう/気にしない), 알레르기(小麦·乳·卵·ナッツ·大豆·えび), 쇼핑 장소(편의점·마트·드럭스토어·백화점) |
| 출력 | 「帰国まで N日 → 帰国後1か月以上もつ商品だけ」 안내 |
| 상태 | ✅ |

### F-03. 추천 엔진 (규칙 필터 → LLM → 검증) — 필수, **핵심**

```
입력(그룹·조건)
  → ① 규칙 필터 (코드): 보관 · 알레르기 · 유통기한 · 매장 유형 · 1인 단가 ≤ 예산×1.15 · 5명 이상이면 개별 포장만
  → ② 점수 정렬 (코드): 격식 일치, 配りやすい, 軽い, 韓国らしい, 예산 근접도
  → ③ LLM: 그룹별 상위 후보 최대 8개만 전달 → 1개 선택 + 일본어 이유
  → ④ 검증 (코드): ID 존재 · 4개 보장 재검사 · 수량/소계/합계 재계산
  → ⑤ 실패 시: 규칙 점수 1순위로 대체, 이유는 템플릿 문장
```

| 항목 | 내용 |
|---|---|
| 출력 | 그룹별 카드: 상품명(ja/ko), 태그, `단가 × 팩 수`, 총 개수, 남는 개수, 소계, 추천 이유, 대체 후보 3개 |
| 화면 | 상단에 「配れる保証」 4개 배지, 하단에 합계·예산 막대·초과 경고 |
| 성능 | LLM 응답 5초 초과 시 ⑤로 대체 (데모 안정성) |
| 상태 | ✅ ①②④⑤ 규칙 버전 / 🔧 ③ LLM 연동, 보장 배지 UI |

**LLM 입출력 계약**

```json
// 요청에 넣는 것: 그룹 정보 + 필터 통과 후보 (id, name_ja, tags, price_per_person)
// 응답 (JSON 스키마 강제)
{
  "groups": [
    { "group_id": "g1", "product_id": "p001", "reason_ja": "個包装で15人に配りやすく、常温で半年もちます。" }
  ]
}
```

### 4-3. 데모 안정성 체크

- [ ] LLM 실패·지연 → 규칙 기반 결과로 자동 전환 (화면에는 티 나지 않게)

## 7. 검증 계획 (과제 발견 15점)

| 방법 | 목표 | 확인하고 싶은 것 |
|---|---|---|
| 일본인 인터뷰 | 10명 이상 | 몇 명에게 · 예산 · 가장 곤란했던 점 · 라벨 경험 |
| 간단 설문 | 30명 이상 | 「人数分そろえるのに困った」 비율 |
| 프로토타입 테스트 | 5명 | 입력부터 구매 카드까지 걸린 시간, 「使いたい」 비율 |

**인터뷰 질문**
1. 韓国旅行でお土産を買うとき、いちばん悩むことは何ですか？
2. 何人くらいに、1人いくらくらいで用意しますか？
3. 韓国語のラベルで困ったことはありますか？
4. このアプリがあったら使いたいですか？（5段階）

**인터뷰에서 '선물 고민'이 약하게 나오면:** 같은 엔진(조건 → 검증된 추천 → 현지 문구)을 다른 과제에 옮길 수 있다. 예: 言いにくいこと代行(말하기 어려운 한국어 문장 대행).
