# 인터뷰 사건·관찰 evidence coding 가이드

작성일: 2026-11-21 · 상태: 첫 인터뷰 전 실행 기준

이 문서는 인터뷰 메모에서 “안내 부족 때문에 새 장소를 포기·지연·대체한 실제 사건”과 안내 예시 관찰을 재사용 가능한 evidence로 만드는 규칙이다. 제품 호감, 진행자 해석과 실제 행동을 한 표에서 섞지 않는 것이 목적이다.

## coding 단위

한 evidence row는 한 참여자의 한 사건 또는 한 안내 예시 과제 관찰이다.

| 종류 | ID | 포함하는 것 | 포함하지 않는 것 |
| --- | --- | --- | --- |
| 실제 사건 | `E-P01-01` | 실제 시점·원래 행동·결정 순간·대체 행동 | 일반 의견·미래 사용 의향 |
| 안내 관찰 | `O-P01-01` | 도움 전 행동·도움 단계·결과 | “좋다”는 평가만 |
| 현장·공식 사실 | `F-R01-01` | 지역 후보의 source·현장 확인 | 참여자 추측 |
| 콘텐츠 사실 | `C-Q01-01` | quest 주소·조건·권리 근거 | 인터뷰 의견 |
| 반대·제외 | `X-01` | 가설·후보를 약화하거나 제외하는 근거 | 마음에 들지 않는다는 팀 취향 |

같은 사건을 여러 문제 pattern에 연결할 수 있지만 독립 사건 수에는 한 번만 센다. 사건 안에 장애물이 여러 개 있어도 행동 전환이 한 번이면 기본적으로 evidence 한 건이다.

## ID 부여

- `P01`은 파일명과 참여자 코드가 같은 세션이다.
- 마지막 두 자리는 해당 참여자 파일 안에서 01부터 증가한다.
- ID를 삭제 후 다른 사건에 재사용하지 않는다.
- interview 파일에서 ID가 처음 정의되고 synthesis·후보 문서는 그 ID를 참조한다.
- ID에 날짜·장소·직업·연락처를 넣지 않는다.
- 같은 사건의 후속 설명은 새 ID가 아니라 기존 row를 보완한다.
- 실제로 다른 시점·장소·결정·대체 행동이면 같은 참여자도 새 `E-*`가 될 수 있다.

안내 이해 테스트만 수행한 세션은 `O-*`만 있을 수 있다. 최근 사건을 재구성하지 못했다면 억지로 `E-*`를 만들지 않고 세션 상태와 제외 이유를 기록한다.

## 실제 사건 E row

최소 필드:

| 필드 | 질문 | unknown 허용 |
| --- | --- | --- |
| evidence ID | 어떤 파일의 몇 번째 사건인가 | 아니오 |
| 시점 범주 | 최근 12개월·그 이전·기억 불명 | 예 |
| 상황 | 혼자 서울에서 무엇을 하려 했는가 | 아니오 |
| 원래 행동 | 처음 하려던 구체 행동 | 아니오 |
| 정보원 | 실제로 본 source 종류 | 예 |
| 확인 정보 | 결정 전에 실제로 알았던 것 | 예 |
| 결정 순간 | 진행·포기·지연·변경한 시점 | 아니오 |
| 부족 정보 | 그 순간 없었던 구체 정보 | 예 |
| 실제 대체 행동 | 결국 한 행동 | 아니오 |
| 비용 | 시간·금액·이동의 관찰 가능한 영향 | 예 |
| 해결 가능성 | P0 안내로 해결 가능·일부·불가 | 해석으로 별도 |

“불안했다”만으로는 사건이 아니다. 무엇을 확인했고 다음에 무엇을 했는지가 있어야 한다. 기억나지 않는 값은 `unknown`으로 두고 진행자 추정으로 채우지 않는다.

## 시간순 재구성

각 사건을 다음 순서로 짧게 쓴다.

```text
trigger → intended action → information checked → decision point
        → missing/known condition → actual next action → consequence
```

인과 표현은 참여자 진술 범위를 넘지 않는다.

- 강한 기록: “혼자 입장 가능한지 찾지 못해 예약 화면을 닫고 이미 가 본 카페로 이동했다.”
- 약한 기록: “정보가 없어서 새로운 경험을 못 한다.”
- 부적절한 해석: “일본인은 한국어가 두려워 모두 익숙한 장소만 간다.”

가격·시간·동행·예약 불가가 유일 원인이면 “안내 부족” evidence로 세지 않는다. 단, 그 조건을 사전에 알 수 없어 불필요한 이동·포기가 생겼다면 정보 timing 문제로 별도 기록할 수 있다.

## 사건 outcome code

| code | 정의 | 예 |
| --- | --- | --- |
| `continued` | 정보 확인 뒤 원래 행동 진행 | 혼자 이용 가능 확인 후 입장 |
| `delayed` | 추가 검색·문의로 진행이 지연 | 여러 후기 교차 확인 |
| `changed` | 비슷한 다른 장소·행동으로 변경 | 다른 매장 선택 |
| `abandoned` | 의도한 새 행동을 하지 않음 | 익숙한 장소로 돌아감 |
| `blocked_external` | 가격·휴무·예약·동행 등 안내 밖 제약 | 최소 2인 조건 |
| `unknown` | 실제 결과를 재구성하지 못함 | 기억 불명 |

outcome code만으로 해결 가능성을 결정하지 않는다. `abandoned`라도 안전·가격 문제면 P0 밖이고, `continued`라도 검색 비용이 컸다면 안내 가치 후보가 될 수 있다.

## 정보 gap code

초기 code는 검색을 돕는 표지이며 새 DB enum이나 제품 filter가 아니다.

| code | 의미 |
| --- | --- |
| `solo_eligibility` | 한 명 이용·최소 인원 |
| `how_to_start` | 입장·주문·예약·첫 행동 |
| `language_phrase` | 현장에서 보여 줄 한국어 표현 |
| `price_condition` | 가격·최소 주문·무료 조건 |
| `time_condition` | 영업·소요·마감 시각 |
| `location_handoff` | 정확한 한국어 주소·출구·층 |
| `what_to_expect` | 단계·준비물·완료 의미 |
| `external_constraint` | 안내로 해결하지 못하는 조건 |
| `unknown` | 구체화 못 함 |

한 사건에 최대 3개만 붙인다. code 수를 늘려 근거가 많아 보이게 하지 않는다. 새 code가 필요하면 기존 code로 표현 불가능한 사건 두 건 이상인지 합성에서 검토한다.

## 안내 예시 O row

최소 필드:

- evidence ID와 stimulus version
- 과제: 가치 설명 / 시작 결정 / 다음 행동 / 한국어 카드
- 도움 전 첫 행동·말
- 성공 / 보류 / 실패 / prototype_issue
- 결정에 사용한 화면 정보
- 5초 뒤 준 prompt 단계
- 도움 후 달라진 행동
- 이해하지 못한 용어·예상 결과
- 실제 사건과 연결되는지 여부

진행자가 설명한 뒤 성공한 결과를 “이해함”으로 합치지 않는다. `prototype_issue`는 참여자 실패 분모에서 제외하지만 UI 결함 evidence로 유지한다.

## 관찰·발언·해석 분리

| 층 | 기록 방식 | 예 |
| --- | --- | --- |
| 관찰 | 보거나 들은 행동·짧은 발언 | “가격을 찾으며 화면을 위아래로 두 번 이동” |
| 참여자 설명 | 식별정보를 제거한 요약 | 혼자 가능한지 먼저 확인한다고 설명 |
| 진행자 해석 | 명시적 가설 | solo 정보가 시작 결정의 선행 조건일 수 있음 |
| 반대 해석 | 다른 가능한 설명 | 가격 위치를 찾던 행동일 수 있음 |
| 확인 질문 | 다음 세션에서 구분할 질문 | 혼자 가능과 가격 중 무엇을 먼저 보는가 |

짧은 인용이 없어도 행동 의미가 유지되면 요약을 우선한다. 말투·문법·희귀 장소 조합이 참여자를 식별할 수 있으면 paraphrase한다.

## 반대 evidence

다음도 evidence로 적극 기록한다.

- 정보가 충분했는데 가격·시간 때문에 포기
- 혼자 가능해도 동행을 선호
- 안내 예시를 이해했지만 시작하지 않음
- 새 장소를 찾지 않고 익숙한 장소만 원함
- 첫 방문자에게만 있고 재방문자에게는 없음
- 진행자 도움 전 가치를 설명하지 못함
- 실제 사건 없이 미래 호감만 표현

반대 evidence는 positive 사건 수에서 빼는 점수가 아니라 가설 범위·무효화 조건을 정한다. 기존 제품 문구와 충돌해도 삭제하지 않는다.

## 독립성 판정

독립 사건으로 셀 수 있음:

- 서로 다른 참여자의 실제 사건
- 같은 참여자라도 다른 시점·장소·결정·대체 행동인 사건

한 건으로 셈:

- 같은 사건을 solo·language·price pattern에 중복 연결
- 질문을 바꿔 같은 답을 다시 들음
- 같은 stimulus의 여러 화면에서 동일 막힘 반복
- 참여자가 들은 다른 사람의 전언

synthesis에는 참여자 수와 사건 수를 함께 쓴다. `3명 5사건`을 `5명`처럼 표현하지 않는다.

## synthesis 승격 규칙

pattern row로 승격하려면:

1. 연결 evidence ID가 있다.
2. 실제 행동과 진행자 해석이 분리돼 있다.
3. 같은 사건 중복을 제거한 참여자·사건 수가 있다.
4. 최소 하나의 반대·대안 설명을 검토했다.
5. 안내로 해결 가능한 범위를 적었다.
6. 남은 unknown과 다음 확인 질문이 있다.

독립 참여자 2명은 D04 “유지 후보”의 최소 조건이지 시장 검증 완료가 아니다. 1명 사건은 버리지 않고 약한 signal로 유지한다.

## 후보 연결

- 지역 후보 점수는 `E-*`와 별도 `F-*` 현장 사실을 모두 요구한다.
- quest 후보는 문제 pattern의 `E-*`, 안내 관찰 `O-*`, 콘텐츠 사실 `C-*`를 구분한다.
- `O-*` 호감만으로 지역·quest 사용자 사례 점수를 올리지 않는다.
- 현장 사실 `F-*`가 좋아도 사용자 문제 `E-*`가 0이면 첫 지역 hard gate를 통과하지 않는다.
- 반대 `X-*`와 unknown은 후보 파일의 제외·무효화 조건에 연결한다.

상세 gate와 점수는 [후보 선택 가이드](CANDIDATE_SELECTION_GUIDE.md)를 따른다.

## 개인정보

- ID에는 참여자 code 외 식별정보를 넣지 않는다.
- 이름·연락처·계정·정확한 숙소·직장·희귀 일정 조합을 제거한다.
- 검색어·지도 기록·메시지 화면 원문을 복사하지 않는다.
- 업체 직원 개인 연락처와 비공개 답변 원문을 evidence로 커밋하지 않는다.
- 녹음·영상·원본 사진은 repository에 넣지 않는다.
- evidence row는 필요한 최소 행동·정보 gap만 남긴다.

## 세션 종료 직후 checklist

- [ ] 파일명·참여자 코드와 모든 `E/O` ID의 `Pxx`가 같음
- [ ] 실제 사건마다 원래 행동·결정 순간·대체 행동이 있음
- [ ] outcome·information gap이 원문보다 강하게 해석되지 않음
- [ ] 관찰·참여자 설명·진행자 해석·반대 해석이 분리됨
- [ ] 도움 전·후와 prototype issue가 분리됨
- [ ] 동일 사건을 여러 evidence ID로 복제하지 않음
- [ ] 개인정보·희귀 식별 조합을 제거함
- [ ] 다음 인터뷰 확인 질문이 하나 있음

## 합성 전 quality gate

- [ ] 모든 합성 evidence ID가 interview 파일에서 정의됨
- [ ] 같은 ID가 서로 다른 사건 설명으로 재사용되지 않음
- [ ] 참여자·사건 수가 중복 제거됨
- [ ] positive·negative·unknown을 함께 읽음
- [ ] O 관찰과 E 사건의 역할을 섞지 않음
- [ ] 지역·quest 점수에 F/C source가 별도로 있음
- [ ] 작은 표본을 일본인 전체 비율로 표현하지 않음
