# LINE 여행 비서 구현 계획

작성일: 2026-11-25 · 상태: 데모 범위 구현 완료, 실제 LINE·KAT 실통화 확인(2026-11-26) · 기준 스펙: [LINE 여행 비서 스펙](LINE_AGENT_SPEC.md) · 실행: [실행 안내](LINE_AGENT_RUNBOOK.md)

11/29 본선 3분 시연이 끝까지 돌아가는 것을 먼저 만들고, 스펙의 나머지는 그 위에 쌓는다. 외부 계정(LINE 채널, OpenAI, Twilio)이 없어도 개발과 시험이 되도록 모든 외부 연동은 어댑터 뒤에 두고, 로컬에서는 시뮬레이터로 대신한다.

## 데모 우선 범위

| 영역 | 이번에 만드는 것 | 뒤로 미루는 것 |
| --- | --- | --- |
| LINE 접점 | 웹훅 서명 검증, 이벤트 중복 제거, 1:1·그룹, 그룹 호출어, 요청자 권한, postback revision 검사, reply/push | 리치 메뉴, LIFF |
| 요청 해석 | 일본어·한국어 규칙 기반 해석(인원, 지역, 메뉴, 도착 마감, 다음 장소), 빠진 항목 하나씩 질문 | LLM 해석 어댑터는 키가 생기면 켬 |
| 후보 | 신촌 큐레이션 후보(최대 3곳), 출처·검수일 표시, 네이버 지역 검색 보충(키 필요) | 실매장 검수 |
| 대기·시간 | 텍스트·캡처 이미지 대기 정보(분·팀 수·원격 대기) 판독, 착석 마감·착석 예상·`fits/late/unknown` 계산 | — |
| 이동 | TMAP 도보(키 있음), 대중교통은 거리 기반 추정치로 표시 | ODsay |
| 전화 | 승인 카드(후보 최대 2곳·후보당 1회·10분 유효), 순차 발신, 통화 결과 판정, 범위 밖 제안·예약금·결과 불명확 처리 | 실매장 발신 |
| 전화망 | 시뮬레이터(로컬·시연 보험), KAT 클라우드(070) 또는 Twilio + GPT-Live 중계(키가 생기면) | SIP 직접 발신 |
| 이동 연결 | `/go` 화면: 식당까지·다음 장소까지, 여기서울 지하철 안내와 네이버지도 링크, 한국어 예약 카드 | 출구 단위 매핑 |
| 저장 | 저장소 인터페이스 + 메모리 구현(로컬·테스트), PostgreSQL 구현과 24시간 정리 | 스펙의 테이블별 분리 |

스펙과 다르게 가는 점: 요청 한 건을 `dining_requests` 한 행(jsonb 본문 + revision)으로 저장한다. 후보·대기·승인·시도는 그 안에 둔다. 발신 시도와 웹훅 이벤트만 별도 테이블로 두어 유니크 제약으로 중복을 막는다. 사흘 안에 끝내기 위한 선택이며, 운영 단계에서 스펙의 테이블로 나눈다.

## 제품 초점과 3분 시연 (2026-11-26)

사용자는 서울을 방문한 일본인 여행자다. 제품이 답하는 순간은 하나로 좁힌다. 식당이든 쇼핑이든 LINE에 가게의 링크·이름·사진을 보내면 "내 조건으로 오늘 가능한가? 가능하면 어떻게 하고, 어렵다면 다음에 뭘 할 수 있나?"에 답한다. 식당은 같은 문제가 해결되는 모습을 보여 주는 대표 사례다. 쇼핑(재고·영업시간 확인)도 같은 흐름이며 이번 시연에서는 말로만 소개한다.

| 단계 | 구현 |
| --- | --- |
| 가게 알아내기 | 네이버 지도 링크(가게 ID, `naver.me` 짧은 링크는 리다이렉트만 따라감), 구글 지도 링크(핀 좌표 60m 이내 또는 이름), 출처로 등록한 페이지, 일본어·한국어 가게 이름, 1:1의 간판 사진(OCR). 인스타그램처럼 열 수 없는 링크는 이름·지도 링크·사진을 달라고 답한다. 등록되지 않은 가게는 아직 정보가 없다고 답한다. |
| 오늘 되나 | 영업시간(네이버 플레이스, 확인일 표시. 라스트오더가 없으면 마감 1시간 전까지 입장), 다음 일정까지의 착석 마감과 이동, 인원. 지금의 빈자리·대기는 가게만 알기 때문에 항상 "확인 필요"로 둔다. 결과는 「行けそう / 確認が必要 / 難しそう」. |
| 되면 어떻게 | AI 전화로 확인·예약(그 가게 먼저, 다음으로 근처 대안), 그냥 가기, 대기 공유. |
| 안 되면 다음 | 근처 같은 메뉴의 가게. 영업시간상 오늘 안 되는 가게에는 전화하지 않는다. |

| 시간 | 시연 | 확인할 결과 |
| --- | --- | --- |
| 0:00–0:30 | LINE에 「このお店、今日2人で行ける？20時までに弘大のライブ会場に着きたい」와 설레임의 네이버 지도 링크를 보낸다. | 링크에서 가게를 알아내고, 영업시간·이동·착석 마감은 ○, 지금의 빈자리는 ？인 판정 카드. |
| 0:30–2:20 | 「AIに任せる」 → 예약명 → 승인(최대 세 곳, 맞으면 거기서 예약). 옆 화면에 AI 전화 콘솔. 설레임은 만석, 돈불은 19시만, 고기창고는 18시 반에 두 명 가능. | 실시간 자막(한국어 + 일본어)과 통화 소리. 사용자가 중간에 고르지 않아도 거절 → 시간 초과(공연에 늦음) → 예약 성공까지 이어진다. 모두 안 되면 가장 가까운 시간으로 늦출지 한 번만 묻는다. |
| 2:20–3:00 | 확정 카드에서 「お店への行き方を見る」. | 여기서울 지하철 안내와 다음 일정까지의 길. |

"Agent i나 파파고와 뭐가 다른가"에 대한 답: Agent i(LINE야후)의 해외여행 에이전트는 계획 단계이고 일본 안의 계획·일정 중심이다. 파파고 트렌드는 네이버 예약이 열린 가게까지 이어 준다. 우리는 온라인 예약이 없는 가게에 AI가 한국어로 전화해 오늘의 빈자리를 확인하고, 다음 일정까지 계산해 안 되면 조건을 유지한 채 다음 가게로 넘어간다. LINE 단톡방에서 일행과 함께 쓴다.

## 진행 상황 (2026-11-26)

| 스펙 항목 | 상태 | 확인 방법 |
| --- | --- | --- |
| 1. LINE과 후보 검색 | 완료: 웹훅 서명·중복 제거, 1:1·그룹(호출어·멘션), 요청자 권한, 인원 분기(1명·5명+·정원 초과 제외), 신촌·성수 테스트 후보 | `agent.test.ts`, `line/line.test.ts` |
| 2. 웨이팅·일정 계산 | 완료: 텍스트·캡처 이미지(OCR) 대기(분·팀 수·원격 대기·입장 시각), 다른 가게 화면 거부, 착석 마감·예상, 기준 미확인 시 질문 | `plan.test.ts` (ETA-01, WAIT-01) |
| 3. 여기서울 이동 연결 | 완료: `/go`(지하철 안내·네이버 지도·역 도감 링크), `/go/card` 한국어 예약 카드 | e2e `line-agent-simulator.spec.ts` |
| 4. 팀원 폰 발신 | 완료: 승인 카드, 순차 발신, 결과 판정, 범위 밖·예약금·불명확·미연결 처리, 음성 중계. KAT 실통화로 한 곳 확정까지 확인(74초, AI 응답 중간값 1.4초). 두 곳 연속(거절 → 수락) 실통화는 아직 | `agent.test.ts` (CALL-01~03), `pnpm voice:selftest`, 시뮬레이터 |
| 5. 기존 체험 연결 | 완료: 원격 대기로 시간이 남을 때 역 주변 미션(모험의 서) 제안, 역 도감(스탬프) 링크 | `agent.test.ts` |
| 저장 | 완료: 메모리(기본), PostgreSQL(`LINE_AGENT_STORE=postgres`, 마이그레이션 0009, 24시간 정리) | `tests/integration/line-agent-store.test.ts` |

실제 연결: LINE 공식 계정 ココソウル이 고정 공개 주소(Tailscale Funnel)로 웹훅을 받고, 실제 LINE 앱에서 요청부터 확정 카드까지 확인했다(전화는 시뮬레이터). 전화망은 KAT 클라우드(070)다. 3분 시연에 두 통화를 넣기 위해 AI 첫마디에 인원과 시간을 함께 묻고, 끝인사 뒤 끊는 대기를 2.5초로 줄였다.

시연 화면: `/dev/line-agent/console`에 실시간 통화 자막(한국어 + 일본어 번역)과 통화별 결과를 보여 준다. 로컬은 PostgreSQL 저장소와 고정 시연 시각(11/29 17:30)으로 리허설한다.

링크·이름·사진으로 가게를 알아내 오늘 되는지 답하는 흐름을 더했다(위 표). 시뮬레이터와 브라우저 테스트로 링크 → 판정 → 전화 → 거절 → 다음 가게 수락까지 확인했다.

시연 전 남은 확인: 실제 LINE 앱에서 네이버 지도 공유 링크(`naver.me`)로 시작해 보기, 거절 → 수락 두 통화를 고정 주소로 실제 발신, 두 통화 포함 3분 시간 재기, 실제 LINE 단톡방 흐름, 신촌 3곳 검수, 리치 메뉴(현재 일본어 이미지 하나).

네이버 지역 검색 보충은 코드 완료(키를 넣으면 켜짐: 큐레이션 후보가 3곳 미만일 때 '검색 후보·확인 안 됨'으로 붙고, 전화하지 않음). 아직 하지 않은 것: LLM 해석 어댑터, 실매장 후보 검수. 리치 메뉴는 `pnpm line:richmenu`로 만든다.
