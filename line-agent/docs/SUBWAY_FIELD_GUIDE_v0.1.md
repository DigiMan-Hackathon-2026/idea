# 지하철 현장 판단·복구 가설 v0.1

작성일: 2026-11-22 · 상태: 사용자 검증 전 demo 계약

## 제품 가설

일본어·역번호·실시간 도착·하차 알림과 일반 경로 검색은 이미 여러 경쟁 앱이 제공한다. 여기서울이 추가로 검증할 문제는 서울에서 혼자 이동하는 일본인 방문객이 경로를 검색한 뒤에도 현장의 개찰구·승강장·행선지를 보고 다음 행동을 확신하기 어렵고, 실수했을 때 경로를 안전하게 복구하기 어렵다는 것이다.

이를 경쟁사에 없는 기능으로 확정하지 않는다. `현장 판단 부담`과 `실수 후 복구`를 기존 앱보다 더 잘 줄일 수 있는지 확인할 가설이다.

## 노선과 환승 안내

웹의 `/subway`에서 1~9호선 일반열차의 출발역과 목적역을 고를 수 있다. 수도권 연장·지선 구간을 포함해 호선별 역번호 458개와 환승역 51곳을 연결한다. 1호선 광명 셔틀·서동탄 지선, 2호선 성수·신정 지선, 5호선 하남·마천 분기, 6호선 응암 일방순환을 반영한다. 예를 들어 김포공항역에서 5호선 승강장은 512, 9호선 승강장은 902로 구분한다.

환승이 적은 경로를 우선하고, 환승 횟수가 같으면 열차 정차역이 적은 경로를 고른다. 환승역에서는 갈아탈 호선의 역번호를 먼저 보여 주고, 해당 승강장에 도착했다고 확인하면 다음 정차역을 표시한다. 예상한 다음 역과 다르면, 열차가 도착한 역 이름·번호를 검색해 이어서 찾을 수 있다. 종착역, 배차, 승강장 위치는 현장 표지와 안내를 확인한다.

9호선 출발역을 선택하면 일반 또는 급행의 정차 순서로 안내할 수 있다. 급행은 운영사가 표시한 김포공항~중앙보훈병원 16개 역에서 선택할 수 있다. 급행이 목적역을 지나가면 준비할 환승역을 먼저 보여 주고, 그 역에 도착했다고 확인하면 일반열차의 다음 정차역으로 갱신한다. 급행 종류, 다음 정차역과 일반열차로 갈아탈 역은 기기에 저장한다. 열차별 종착역과 운행 여부는 [서울시메트로9호선 공식 시간표](https://www.metro9.co.kr/prog/subwayTm/kor/sub01_02/list.do)와 현장 표시를 확인한다.

역 순서와 환승은 [서울교통공사 수도권 지하철 노선도](https://www.data.go.kr/data/15120713/fileData.do) 및 [국토교통부 철도역 빠른 환승 정보](https://www.data.go.kr/data/15151816/fileData.do)로 대조했다. 번호는 [서울교통공사 역명 지하철역 검색](https://data.seoul.go.kr/dataList/OA-121/S/1/datasetView.do)의 외부코드 기준이다. 영문·일문 역명은 [서울교통공사 역명 다국어 표기](https://www.data.go.kr/data/15044232/fileData.do), [철도산업정보센터 코레일 역정보](https://data.kric.go.kr/rips/M_01_01/detail.do?id=79&lcd=A), 국가철도공단의 [4호선](https://www.data.go.kr/data/15041806/fileData.do), [6호선](https://www.data.go.kr/data/15041809/fileData.do), [7호선](https://www.data.go.kr/data/15064046/fileData.do), [8호선](https://www.data.go.kr/data/15041810/fileData.do), [9호선](https://www.data.go.kr/data/15041811/fileData.do) 자료에서 확인했다. 연천 연장 3개 역과 일부 코레일 역은 한글 역명을 기준으로 일본어 읽기를 보완했다.

출발역과 목적역을 선택하면 현재 이동 한 건을 브라우저에 저장한다. 마지막으로 확인한 정차역과 필요한 환승 안내는 같은 기기에서 다시 연다. 도착 또는 하차를 확인할 때 저장된 역을 갱신한다. 서비스 워커가 설치된 브라우저에서 연결 없이 `/subway`를 열면 정적 화면이 저장된 역, 다음에 대조할 역 또는 갈아탈 호선의 역번호와 한국어 도움 문장을 보여 준다. 현재 운행은 현장에서 확인한다. 이동 정보 삭제는 이 브라우저의 지하철 안내 한 건에 적용한다.

## 역 내부 안내 검색

현재 위치에서 가까운 역을 찾으면 [서울시 역사마스터 좌표](https://www.data.go.kr/data/15171250/fileData.do)를 사용해 기기에서 직선거리를 계산한다. 가장 가까운 역 최대 세 곳과 환승 호선을 보여주고, 사용자가 표지와 대조해 선택하면 해당 호선의 안내를 연다. 좌표는 저장하거나 전송하지 않는다. GPS 오차가 크면 역 이름 또는 번호로 검색할 수 있다.

`/subway`에서 1~9호선의 호선별 역번호 458개를 검색하거나 이동 안내의 내릴 역을 바로 열 수 있다. 서울교통공사의 [공식 역이용안내도](https://data.seoul.go.kr/dataList/OA-11984/S/1/datasetView.do) 중 역이름과 호선이 일치하는 269장을 WebP로 제공한다. 6호선 봉화산역은 원본에 두 장이 있어 더 최근 파일을 사용한다. 도면은 배포 원본의 한국어 표기를 유지한다.

국가철도공단의 호선별 승강장 자료와 [코레일 승강장 정보](https://www.data.go.kr/data/15041187/fileData.do)에서 확인한 층을 보여준다. 진접·오남·별내별가람은 [남양주도시공사 자료](https://www.ncuc.or.kr/File/42a594550807bcbaa3b14475b475f6fd)의 층과 역별 공식 안내도를 연결한다. 탕정역은 코레일이 공개한 역사 규모를 표시한다. 별도 도면이 없는 역에서는 [레일포털 철도역 운영 정보](https://station.kric.go.kr/v2/altmInfoSys/index.do)로 시설을 확인할 수 있다.

## 성수역 2D 층별 안내 계약

3D 지도를 핵심 안내로 쓰는 것은 보류한다. S-MAP은 지하철 역사 실내 3D를 제공하지만 모바일 지원과 외부 서비스 연동 범위가 확정되지 않았고, 현장에서 빠르게 다음 행동을 고르는 목적에는 회전 가능한 3D보다 단순한 2D가 적합하다는 제품 판단이다. 대신 사용자가 실제 구조를 추가로 확인할 수 있도록 S-MAP을 새 창에서 여는 보조 링크를 제공한다.

2026-11-22 S-MAP 공개 응답 `getSubwayData.do`에서 성수역 모델 `211_U_SB_191113`을 확인했다. 응답의 층 메타데이터는 `1F` 한 건뿐이어서 층별 동선을 보장하는 자료로 해석하지 않는다. 공개된 역 전용 딥링크와 외부 임베드 API도 확인되지 않아, 사용자가 S-MAP에서 `성수역`을 다시 검색하도록 안내한다.

사용자는 GPS나 자동 실내 위치를 신뢰하는 대신 현재 보이는 층과 개찰구 안팎을 직접 선택한다.

- 3F 승강장
- 2F 개찰구 안쪽
- 2F 개찰구 바깥쪽
- 1F 3번 출구 앞

선택 뒤에는 다음 정보를 제공한다.

1. `3F 승강장 → 2F 개찰구·대합실 → 1F 3번 출구`의 층 관계
2. 공식 역이용안내도의 층·출구 방향 관계를 단순화한 2D 개념도와 현재 위치 표시
3. 다음 분기점에서 대조할 한글·영문·일문·역번호 표지 카드
4. 추측하지 않고 수행할 다음 행동 하나
5. 역무원에게 보여 주거나 복사할 한국어 도움 요청

개념도는 건축 평면도나 정확한 보행 경로가 아니다. 현장 공사·통제와 표지판이 화면보다 우선한다. 실제 통로 모양과 분기점 사진은 촬영일·위치·방향·이용 권리를 검수한 뒤에만 추가한다.

성수역 공식 안내도에서 확인해 demo에 반영한 관계는 다음으로 제한한다.

- 3F에 승강장이 있고 2F로 내려가 개찰구·대합실을 거쳐 1F 출구로 이동한다.
- 1·4번 출구는 뚝섬·용답 쪽, 2·3번 출구는 건대입구 쪽으로 표시돼 있다.
- 3번 출구 이용자는 2F에서 `2·3번 출구·건대입구 방면`을 먼저 확인한 뒤 마지막 분기에서 `3`을 확인한다.
- 2F 대합실에는 고객안내센터, 화장실, 승차권 발매·교통카드 충전기와 수유실이 표시돼 있다.
- 공식 안내도에는 3F와 2F, 2F와 1F를 잇는 계단·에스컬레이터·엘리베이터가 구분돼 있다. 화면은 시설 존재만 보여 주며 정확한 위치와 운행 상태는 현장 표지와 API 상태를 우선한다.
- 3번 출구에는 에스컬레이터가 표시돼 있지만 지상 연결 엘리베이터 공식 정보는 없다. 지상 연결 엘리베이터는 API에서 확인된 1·4번 출구만 안내한다.

출처 파일은 서울 열린데이터광장의 `서울교통공사 역이용안내도` 최신 ZIP이다. 데이터 페이지 게시일은 2026-08-24이지만 성수역 이미지 내부 표기는 2024-04-16이므로 둘을 성수역 개념도에 함께 표시한다.

## 서울교통공사 API 연결

server는 공공데이터포털의 서울교통공사 API 두 개를 5분 단위로 재검증한다.

| 정보 | operation | 화면 사용 |
| --- | --- | --- |
| 엘리베이터 | `B553766/wksn/getWksnElvtr` | 조회 성공 건수와 점검·고장·중지 등 확인 필요 상태 경고 |
| 빠른 하차 | `B553766/inout/getFstExit` | 방면, 성수역 하차 시 참고할 차량 출입문 번호, 연결 설비 |

인증키는 server-only `SEOUL_METRO_PUBLIC_DATA_SERVICE_KEY`로만 읽고 client, HTML, 오류 로그에 전달하지 않는다. 키가 없거나 provider가 실패하면 추정 데이터를 만들지 않고 `연결 준비 중` 또는 `불러오지 못함`과 현장 확인 행동을 두 언어로 보여 준다. 한 API만 성공하면 성공한 정보만 공개한다.

빠른 하차의 차량 출입문 번호는 성수역에서 내릴 때의 참고 정보이며, 탑승 방향·운행 장애·실제 설비 이용 가능성을 보장하지 않는다. 원문에 없는 일본어를 임의 생성하지 않고 검수된 방향·역·설비 이름만 대응시킨다.

사용자에게 상·하행 전체 목록을 그대로 보여 주지 않는다. 성수역 직전 역과 이동 방법을 선택하게 하고 공식 방면 정보와 다음처럼 대응한다.

| 직전 역 | 성수역 뒤 진행 방면 | 우선 표시 |
| --- | --- | --- |
| 뚝섬 | 건대입구 | 건대입구 방면 빠른 하차 정보 |
| 건대입구 | 뚝섬 | 뚝섬 방면 빠른 하차 정보 |
| 용답·모름 | 대응 확정 안 함 | 차량 문을 추측하지 않고 `Way out`·역무원 확인 |

승강기 `oprtngSitu`는 서울 열린데이터광장 공식 코드표에 따라 `M 사용 가능`, `D 삭제`, `S 보수 중`, `T 중지`, `I 점검 중`, `B 공사 중`으로 해석한다. 알 수 없는 값은 사용 가능으로 취급하지 않는다. API 조회 시각과 각 행의 데이터 기준일은 구분해 표시한다.

2026-11-22 응답에서 성수역 지상 연결 승강기는 1번·4번 출입구, 승강장 연결 승강기는 뚝섬 방면 7-1·건대입구 방면 4-4로 확인됐다. 3번 출구에 지상 연결 승강기가 있다고 안내하지 않는다. 계단 이용이 어려우면 1번·4번 중 목적지에 맞는 출구를 역무원에게 확인하고 지상에서 도보 경로를 다시 검색하도록 한다. 도로 횡단 안전성이 검증되기 전 특정 우회 출구를 자동 추천하지 않는다.

## 복구 계약

사용자는 정상 경로 화면에서 바로 다음 세 가지 복구 상황을 선택할 수 있다.

- 다른 승강장에 있음: 선로를 넘지 않고 2F 대합실에서 확인
- 다른 개찰구로 나옴: 교통카드를 다시 찍기 전에 역무원에게 개찰구 밖 연결 확인
- 다른 출구로 나옴: 무리한 도로 횡단 없이 현재 출구 기준으로 보행 경로 재검색

출발역과 실제 탑승 열차를 모르면 방향·승강장·환승 동선을 추측하지 않는다. NAVER 지도에서 경로를 다시 확인하거나 역무원에게 묻는 행동을 먼저 제공한다.

## 콘텐츠 신뢰 경계

- 성수역의 2호선·외부 역번호 `211`은 서울교통공사 공개 데이터에서 확인한 demo 사실이다.
- 성수역 공식 역이용안내도의 3F·2F·1F 층 관계와 출구 방향은 화면에서 단순화하며 정확한 평면 형상으로 주장하지 않는다.
- 실시간 열차 위치·도착·운행 장애는 여기서울이 제공하거나 보장하지 않는다.
- 역별 개찰구 연결·승강장 방향·환승 분기·현장 사진은 출처와 확인 시각을 가진 콘텐츠로 별도 검수하기 전에는 확정 안내로 공개하지 않는다.
- 현재 화면은 동선 정확도를 입증한 운영 콘텐츠가 아니라 상황형 안내의 사용성을 검증하는 demo다.
- 성수역 출입구 증설 공사로 동선이 바뀔 수 있으므로 `검증 기준일`을 화면에 표시하고 현장 표지를 우선하도록 안내한다.

## 검증 방법

같은 참가자가 기존 지도 앱과 여기서울 시제품으로 서로 다른 경로를 수행하고 사용 순서를 바꾼다.

| 지표 | 관찰 내용 |
| --- | --- |
| 판단 정확도 | 올바른 개찰구·승강장·열차를 선택했는가 |
| 확인 부담 | 멈춤·화면 전환·재검색 횟수가 줄었는가 |
| 독립적 이용 | 다른 사람의 개입 없이 다음 행동을 정했는가 |
| 복구 능력 | 실수 뒤 올바른 경로로 돌아왔는가 |
| 확신과 정확성 | 자신감뿐 아니라 실제 판단도 개선됐는가 |

기존 앱보다 현장 문제를 더 정확하고 적은 부담으로 해결한다는 관찰이 반복될 때만 지하철 전문 서비스로 범위를 좁힌다.
